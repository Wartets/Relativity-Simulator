# Technical Architecture & System Design

## 1. Architectural Principles & System Paradigms

The Relativistic Engine is an ISO C++23 simulation and visualization framework for relativistic mechanics and raytracing. The system is structured into six functional layers:
- Application Lifecycle & Platform Bootstrap Layer: Operating-system integration, per-monitor DPI scaling, single-instance inter-process synchronization, asset path normalization, and asynchronous staged splash progress monitoring ([Section 2.15](#215-application-lifecycle-platform-bootstrap--startup-window-subsystem)).
- Core Analytical & Numerical Physics Engine: Stateless, thread-parallel libraries executing [tensor algebra](TECHNICAL_MANUAL.md#21-static-tensor--simd-algebra-layer), [geodesic integration](TECHNICAL_MANUAL.md#23-differential-solvers--integrators), [post-Newtonian multi-body dynamics](MATHEMATICAL_FORMULATION.md#3-post-newtonian-pn-n-body-dynamics), [relativistic hydrodynamics](MATHEMATICAL_FORMULATION.md#4-relativistic-hydrodynamics-grhdgrmhd), and [uncertainty quantification](MATHEMATICAL_FORMULATION.md#7-uncertainty-quantification-formulation).
- Simulation Runtime & State Orchestrator: A synchronous deterministic state machine driven by a [fixed logical time-step scheduler](#31-deterministic-simulation-scheduler), communicating with external control layers via [lock-free SPSC queues](#32-asynchronous-lock-free-command-queue).
- Render & Compute Pipeline: Hardware-accelerated GPU compute pipelines ([Vulkan compute](#29-render-pipeline)) and multithreaded SIMD software compute engines ([SoftwareComputeEngine](TECHNICAL_MANUAL.md#29-rendering-back-ends)) performing [backward null geodesic raytracing](MATHEMATICAL_FORMULATION.md#8-image-formation-in-the-renderer), [polarized radiative transfer](MATHEMATICAL_FORMULATION.md#6-polarized-radiative-transfer), and [spectral reduction](DESCRIPTION.md#93-continuous-spectral-pipeline--cie-1931-integration).
- Presentation, Instrumentation & Workspace Layer: An interactive multi-window graphical user interface with docking workspaces ([UI Architecture](#52-graphical-multi-window-workspace-ui-architecture)), real-time telemetry dashboards ([Telemetry & Diagnostics](TECHNICAL_MANUAL.md#28-orchestration-scheduling--user-interface)), spectrographs, and a non-blocking [master command-line interpreter (REPL)](#51-master-terminal-loop-repl).
- Distributed Compute & Heterogeneous Cluster Layer: A decoupled network execution extension ([Section 2.14](#214-distributed-compute-subsystem--heterogeneous-cluster-architecture)) providing authenticated, latency-weighted parallel dispatch across network worker instances.

### Fundamental Design Paradigms

- Zero-Allocation Hot Path: Differential equations, tensor contractions, raytracing passes, and uncertainty loops execute without dynamic heap allocations. Core structures utilize pre-allocated memory arenas (`LinearMemoryArena`, `include/relativistic/core/memory_arena.hpp`) aligned to 64-byte and 128-byte cache boundaries ([Technical Manual](TECHNICAL_MANUAL.md#11-design-constraints)).
- Static Compile-Time Polymorphism: Elimination of virtual table dispatch across inner loops through C++23 concepts (`SpacetimeMetric`, `include/relativistic/metrics/spacetime_concept.hpp`) and template specializations.
- Explicit SIMD Register Vectorization: Use of explicit vectorization abstractions (`SimdVec<T, Width>`, `SimdMask<T, Width>`, `include/relativistic/core/simd.hpp`, and `GeodesicBundle<T, Width>`, `include/relativistic/core/geodesic_bundle.hpp`) processing multiple geodesic rays and phase states concurrently across AVX2, AVX-512, and ARM Neon architectures ([Section 4.3](#43-simd-register-vectorization)).
- Strict Bit-Level Determinism: Guaranteed reproducibility across identical hardware targets via explicit-state pseudo-random number generators (`PCG64Engine`, `include/relativistic/core/pcg64.hpp`) and fixed-step temporal scheduling ([Section 3.1](#31-deterministic-simulation-scheduler)).

## 2. Core Subsystems & Computational Hierarchy

The system architecture is organized into modular subsystems operating across decoupled boundaries:

### 2.1. Tensor Algebra & Curvature Evaluation Layer

- Static Tensor Primitives: `Tensor<T, Rank, Dim>` (`include/relativistic/core/tensor.hpp`) defines cache-aligned multidimensional tensor storage with compile-time rank, dimension, and flat index resolution ([Technical Manual](TECHNICAL_MANUAL.md#21-static-tensor--simd-algebra-layer)).
- Metric Inversion & Contraction: `inverse_metric_4x4` and `determinant_4x4` perform analytical cofactor inversions for 4D spacetime metrics; `contract` and `contract_tensors` (`include/relativistic/core/tensor_ops.hpp`) execute general Einstein summation contractions.
- Christoffel Evaluation: `compute_christoffel` (`include/relativistic/core/christoffel.hpp`) dynamically dispatches to exact analytical formulations when provided by the metric or evaluates numerical derivatives via 8th-order centered finite difference stencils (`compute_christoffel_numerical`; see [Mathematical Formulation](MATHEMATICAL_FORMULATION.md#21-christoffel-symbols-of-the-second-kind)).
- Curvature Invariants: `RiemannComputer` (`include/relativistic/core/riemann.hpp`) computes the Riemann tensor $R^\rho_{\phantom{\rho}\sigma\mu\nu}$, Ricci tensor $R_{\mu\nu}$, Ricci scalar $R$, and Kretschmann invariant $K_1 = R^{\alpha\beta\gamma\delta} R_{\alpha\beta\gamma\delta}$ ([Mathematical Formulation](MATHEMATICAL_FORMULATION.md#23-riemann-tensor-ricci-tensor--kretschmann-scalar)).

### 2.2. Spacetime Metric Modules

Every spacetime implementation satisfies the `SpacetimeMetric` concept (`include/relativistic/metrics/spacetime_concept.hpp`), requiring `metric_tensor`, `inverse_metric`, `christoffel_symbols`, and `speed_of_light`:
- Analytical Vacuum Spacetimes: `FlatMinkowskiMetric` ([MATHEMATICAL_FORMULATION.md Section 1.1](MATHEMATICAL_FORMULATION.md#11-minkowski-metric-flat-spacetime)), `SchwarzschildMetric` ([Section 1.2](MATHEMATICAL_FORMULATION.md#12-schwarzschild-metric)), and `KerrMetric` ([Section 1.3](MATHEMATICAL_FORMULATION.md#13-kerr-metric-rotating-black-hole)).
- Regularized Coordinate Gauges: `SchwarzschildIsotropicMetric`, `PainleveGullstrandMetric`, `EddingtonFinkelsteinMetric`, and Cartesian `KerrSchildMetric` ([Section 1.3](MATHEMATICAL_FORMULATION.md#13-kerr-metric-rotating-black-hole)).
- Electrovacuum & Cosmological Spacetimes: `ReissnerNordstromMetric` ([Section 1.4](MATHEMATICAL_FORMULATION.md#14-reissner-nordström-metric-charged-black-hole)), `KerrNewmanMetric` ([Section 1.5](MATHEMATICAL_FORMULATION.md#15-kerr-newman-metric-charged-rotating-black-hole)), `SchwarzschildDeSitterMetric` ([Section 1.6](MATHEMATICAL_FORMULATION.md#16-schwarzschild-de-sitter--kottler-metric)), `FLRWMetric` ([Section 1.7](MATHEMATICAL_FORMULATION.md#17-flrw-metric-cosmological-spacetime)), `LemaitreTolmanBondiMetric` (`LtbProfile`, [Section 1.10](MATHEMATICAL_FORMULATION.md#110-lemaitre-tolman-bondi-void-metric)), `QuintessenceCosmologyMetric` (`QuintessenceBackground`, `ExpansionHistoryBuilder`, [Section 1.11](MATHEMATICAL_FORMULATION.md#111-quintessence-dark-energy-cosmology)), and `ChaplyginCosmologyMetric` (`ExpansionHistoryBuilder::build_chaplygin`, [Section 1.12](MATHEMATICAL_FORMULATION.md#112-chaplygin-gas-cosmology)).
- Exotic & Semiclassical Spacetimes: `MorrisThorneWormholeMetric` ([Section 1.8](MATHEMATICAL_FORMULATION.md#18-morris-thorne-traversable-wormhole)), `AlcubierreWarpMetric` ([Section 1.9](MATHEMATICAL_FORMULATION.md#19-alcubierre-warp-drive-metric)), `EvaporatingVaidyaMetric` (`HawkingRadiation`, `RenormalizedStressTensor`, `EvaporatingBlackHole`, `UnruhEffect`, [Section 1.13](MATHEMATICAL_FORMULATION.md#113-evaporating-vaidya-black-hole-metric)), and `TeVeSSpacetimeMetric` ([Section 1.14](MATHEMATICAL_FORMULATION.md#114-teves-tensor-vector-scalar-metric)).
- Conformal 3+1 Numerical Relativity: `BssnGrid` (`include/relativistic/metrics/bssn_grid.hpp`) manages 3D spatial field representations ($\phi, K, \tilde{\gamma}_{ij}, \tilde{A}_{ij}, \tilde{\Gamma}^i, \alpha, \beta^i$), `BssnEvolution` (`include/relativistic/metrics/bssn_evolution.hpp`) implements 4th-order spatial finite differencing with RK4 time stepping, `BssnConstraints` (`include/relativistic/metrics/bssn_constraints.hpp`) evaluates Hamiltonian constraint residuals, and `TricubicInterpolator` / `QuinticHermiteTimeInterpolator` (`include/relativistic/metrics/bssn_interpolation.hpp`) provide spatial and temporal metric field evaluations ([Description](DESCRIPTION.md#44-31-numerical-relativity-grids-bssn)).
- Runtime tracer dispatch per metric is tabulated in [TECHNICAL_MANUAL.md](TECHNICAL_MANUAL.md#metric-usage-in-softwarecomputeengine).

### 2.3. Differential Solvers & Geodesic Integrators

- Embedded Adaptive Solvers: `RK45AdaptiveIntegrator` (Dormand-Prince 5(4), `include/relativistic/integrators/rk45_adaptive.hpp`) and `CashKarpIntegrator` (`include/relativistic/integrators/cash_karp.hpp`) provide variable-step integration with automatic infalling radial step-size regulation ($0.5 r / |u^r|$) and algebraic constraint projection ($g_{\mu\nu} u^\mu u^\nu = \text{const}$) solving the quadratic polynomial for $u^0$ to machine precision ([MATHEMATICAL_FORMULATION.md Section 18.1](MATHEMATICAL_FORMULATION.md#181-embedded-adaptive-runge-kutta-tableaus-dormand-prince--cash-karp) and [Section 18.6](MATHEMATICAL_FORMULATION.md#186-algebraic-invariant-constraint-projection--horizon-boundary-classification)).
- High-Order Extended Solvers: `Vernier9Integrator` (`include/relativistic/integrators/vernier9.hpp`) implements a 16-stage 9(8) embedded Runge-Kutta scheme optimizing truncation error bounds for long orbital baselines ([MATHEMATICAL_FORMULATION.md Section 18.2](MATHEMATICAL_FORMULATION.md#182-vernier-98-high-order-16-stage-embedded-runge-kutta-scheme)).
- Symplectic Solvers: `GaussLegendreIntegrator` (`include/relativistic/integrators/symplectic_gauss_legendre.hpp`) provides implicit Runge-Kutta schemes (orders 4 and 6, `GaussLegendre4` and `GaussLegendre6`) satisfying $b_i A_{ij} + b_j A_{ji} - b_i b_j = 0$ with Picard fixed-point stage iterations to tolerance $10^{-14}$, preserving phase-space symplectic 2-forms and Killing invariants ([MATHEMATICAL_FORMULATION.md Section 18.3](MATHEMATICAL_FORMULATION.md#183-implicit-symplectic-gauss-legendre-integrators-orders-4-and-6)).
- Predictor-Corrector Solvers: `Hermite4AarsethIntegrator` (`include/relativistic/integrators/hermite4_aarseth.hpp`) evaluates acceleration $\mathbf{a}$, 4th-order centered finite difference jerk $\mathbf{j}$, snap $\mathbf{s}$, and crackle $\mathbf{c}$ with Aarseth variable timestep regulation $\Delta t \propto \sqrt{(\|\mathbf{a}\| \|\mathbf{s}\| + \|\mathbf{j}\|^2) / (\|\mathbf{j}\| \|\mathbf{c}\| + \|\mathbf{s}\|^2)}$ for close gravitational encounters ([MATHEMATICAL_FORMULATION.md Section 18.4](MATHEMATICAL_FORMULATION.md#184-hermite-4th-order-predictor-corrector-scheme--aarseth-adaptive-timestep)).
- Adaptive Step-Size Controllers: `AdaptiveStepController` (`include/relativistic/integrators/step_controller.hpp`) implements `Standard` (integral filter), `PI30` (proportional-integral filter), and `PID42` (proportional-integral-derivative filter) to eliminate step-size chattering across sharp curvature gradients ([MATHEMATICAL_FORMULATION.md Section 18.5](MATHEMATICAL_FORMULATION.md#185-digital-filter-adaptive-step-size-controllers-standard-pi30-pid42)).
- Horizon Boundary Handling: `HorizonDetector` (`include/relativistic/integrators/horizon_manager.hpp`) evaluates a state machine tracking trajectory radial distance against horizon radius $r_s$ and singularity threshold $\delta_{\text{sing}} r_s$, executing absorption or interior continuity ([MATHEMATICAL_FORMULATION.md Section 18.6](MATHEMATICAL_FORMULATION.md#186-algebraic-invariant-constraint-projection--horizon-boundary-classification)).
- Specialized Null Geodesic Integrators: `step_planar_null_rk4` (`include/relativistic/core/spherical_planar_null_integrator.hpp`), `step_schwarzschild_null_rk4` (`include/relativistic/core/schwarzschild_null_integrator.hpp`), and Cartesian `step_kerr_schild_null_rk4` (`include/relativistic/core/kerr_schild_null_integrator.hpp`) provide optimized RK4 geodesic stepping with angular momentum conservation, exact central potential accelerations, and Gram-Schmidt observer tetrad constructions ([MATHEMATICAL_FORMULATION.md Section 18.7](MATHEMATICAL_FORMULATION.md#187-specialized-null-geodesic-differential-integrators)).
- Runtime integration selection rules for N-body dynamics versus image ray tracing are detailed in [TECHNICAL_MANUAL.md](TECHNICAL_MANUAL.md#runtime-use-of-the-integrator-selection).

### 2.4. Post-Newtonian Dynamics & Gravimetry

- Multi-Body Formulations: `PostNewtonianSolver` (`include/relativistic/dynamics/pn_acceleration.hpp`) and `PostNewtonianSystem` (`include/relativistic/dynamics/pn_nbody_system.hpp`) evaluate multi-body equations of motion from Newtonian up to 3.5PN order, including 2.5PN radiation damping, spin-orbit, spin-spin, and self-spin interactions ([Mathematical Formulation](MATHEMATICAL_FORMULATION.md#3-post-newtonian-pn-n-body-dynamics)).
- Gravitational Radiation: `GravitationalWaveCalculator` (`include/relativistic/dynamics/pn_gravitational_waves.hpp`) extracts trace-free quadrupole moments and evaluates radiation reaction power $P_{\text{GW}}$ and waveform strain polarizations $(h_+, h_\times)$ ([MATHEMATICAL_FORMULATION.md Section 3.4](MATHEMATICAL_FORMULATION.md#34-gravitational-wave-quadrupole-emission)).
- Planetary Gravimetry: `SphericalHarmonicsGravityModel` (`include/relativistic/gravimetry/spherical_harmonics.hpp`) and `AssociatedLegendreTable` (`include/relativistic/gravimetry/legendre_table.hpp`) execute fully normalized spherical harmonic potential and acceleration evaluations up to degree and order 32, coupled with `TidalPerturbationModel` (`include/relativistic/gravimetry/tidal_perturbations.hpp`) Love number modifications ([Description](DESCRIPTION.md#52-spherical-harmonics--high-degree-geodesy)).
- Analytical Precession: `OrbitalPrecessionAnalytic` (`include/relativistic/gravimetry/orbital_precession.hpp`) computes secular nodal and apsidal drift rates ($J_2, J_4$).

### 2.5. Dark Matter & Modified Gravity

- Density Profiles: `DarkMatterProfileMath` (`include/relativistic/dark_matter/dark_matter_field.hpp`) evaluates enclosed mass, radial derivative, and density for 13 analytic profiles: `NavarroFrenkWhite`, `Hernquist`, `Burkert`, `Einasto`, `Plummer`, `CoredIsothermal`, `SingularIsothermal`, `Dehnen`, `PointMass`, `Jaffe`, `Moore`, `Soliton`, and `BetaModel` ([Mathematical Formulation Section 17.1](MATHEMATICAL_FORMULATION.md#171-analytic-density-profiles--enclosed-mass)); standalone templates `NFWProfile`, `EinastoProfile`, `BurkertProfile`, and `HernquistProfile` (`include/relativistic/dark_matter/dark_matter_profiles.hpp`) evaluate analytical gravitational potentials, accelerations, and circular velocity curves.
- Multi-Halo Field & Lensing Engine: `DarkMatterHaloSettings` and `DarkMatterFieldSettings` (`include/relativistic/dark_matter/dark_matter_field.hpp`) manage catalog storage up to 32 halos, 11 archetypes (`DarkMatterHaloPreset`), triaxial axis ratios ($q_y, q_z$), Tait-Bryan Euler orientations, and Keplerian orbital kinematics (`DarkMatterHaloOrbit`). `DarkMatterLensing` evaluates perpendicular geodesic deflection kicks with step limiters, while `ResolvedDarkMatterField` evaluates N-body body accelerations and emissive density/field/velocity rendering.
- Layout & Population Generation: `DarkMatterFieldSettings::spawn_layout` synthesizes five geometric configurations (`DarkMatterLayoutPattern`: Ring, BinaryPair, LinearChain, CubicLattice, SphericalShell); `DarkMatterFieldSettings::spawn_population` generates subhalo populations with power-law mass and radial distributions (`DarkMatterPopulationSettings`).
- N-Body Collisionless Dynamics: `BarnesHutOctree` (`include/relativistic/dark_matter/barnes_hut.hpp`) executes hierarchical octree spatial partitioning with quadrupole multipole expansions and symplectic leapfrog advancement for collisionless particle collections (`CollisionlessParticle`).
- Composite Galaxy Synthesis: `CompositeGalaxyGenerator` (`include/relativistic/dark_matter/galaxy_model.hpp`) synthesizes multi-component galaxies comprising exponential disks, Hernquist bulges, and NFW halos with dispersion kinematics and barycenter evaluation.
- Modified Gravity Solvers: `MondFramework` (`include/relativistic/modified_gravity/mond.hpp`) implements non-linear MOND interpolation functions ($\mu, \nu$), `TeVeSSpacetimeMetric` (`include/relativistic/modified_gravity/teves.hpp`) solves the covariant Tensor-Vector-Scalar metric, and `FRChameleonModel` (`include/relativistic/modified_gravity/f_r_gravity.hpp`) computes scalar-tensor field screening.

### 2.6. Relativistic Hydrodynamics (GRHD/GRMHD)

- State & Flux Containers: `PrimitiveVariables`, `ConservedVariables`, and `FluxVariables` (`include/relativistic/hydro/hydro_types.hpp`) encapsulate rest-mass density $\rho$, isotropic gas pressure $p$, 3-velocity components $(v_x, v_y, v_z)$, lab-frame magnetic components $(B_x, B_y, B_z)$, specific internal energy $\varepsilon$, Lorentz factor $W$, specific enthalpy $h$, and comobile magnetic energy density $b^2$ aligned to 64-byte cache boundaries, with `recompute_derived` enforcing velocity sub-luminality $v^2 \le 1 - 10^{-15}$ ([Mathematical Formulation](MATHEMATICAL_FORMULATION.md#42-conservative-31-form)).
- Primitive-to-Conserved and Flux Projections: `prim_to_con_flat` converts primitive arrays into conserved variables $(D, S_x, S_y, S_z, \tau, B_x, B_y, B_z)$, while `compute_flux_1d_x` evaluates the 1D directional physical flux vector along grid axes, and `Metric3Plus1` defines lapse $\alpha$, shift $\beta^i$, 3-metric $\gamma_{ij}$, and extrinsic curvature $K_{ij}$ ([Mathematical Formulation](MATHEMATICAL_FORMULATION.md#42-conservative-31-form)).
- High-Order Spatial Reconstruction: `WENO5Reconstructor` evaluates 5th-order weighted essentially non-oscillatory interface stencils supporting Jiang-Shu and WENO-Z $\tau_5 = |\beta_0 - \beta_2|$ smoothness indicators; `MP5Reconstructor` applies Suresh-Huynh monotonicity-preserving limiters with minmod4 curvature bounds and median selection ($\alpha = 4.0$); `TVDReconstructor` provides second-order MinMod and Monotonized Central (MC) slope-limited cell interfaces, applied across primitive states with physical density and pressure floors ($\rho \ge 10^{-15}, p \ge 10^{-15}$) via `reconstruct_primitive_variable_component` (`include/relativistic/hydro/solvers/reconstruction.hpp`, [Mathematical Formulation](MATHEMATICAL_FORMULATION.md#45-high-order-spatial-reconstruction-schemes)).
- Multi-Wave Approximate Riemann Solvers: `HLLRiemannSolver` computes two-wave intermediate state fluxes; `HLLCRiemannSolver` restores the central contact wave structure by solving the quadratic dispersion relation for star-state wave speed $\lambda_*$ and pressure $p_*$; `HLLDRiemannSolver` resolves five-wave intermediate Alfvén and slow magnetosonic discontinuities when transverse magnetic fields are non-zero (`include/relativistic/hydro/solvers/riemann_solvers.hpp`, [Mathematical Formulation](MATHEMATICAL_FORMULATION.md#46-multi-wave-approximate-riemann-solvers)).
- Conserved-to-Primitive Inversion: `Con2PrimSolver` (`include/relativistic/hydro/solvers/con2prim.hpp`) converts conserved states to primitives via `solve_hydro` executing bracketed 1D Newton-Raphson root-finding on gas pressure $p$ with analytical derivatives $df/dp = \Gamma - (\Gamma - 1)v^2(1 - 1/h)$ and bisection fallbacks on $[p_{\min}, p_{\max}]$, and via `solve_mhd` executing 1D root-finding on scalar $z = \rho h W^2$ with comobile magnetic field coupling $b^2 = B^2/W^2 + (\mathbf{S}\cdot\mathbf{B})^2/z^2$ and explicit 3-velocity vector reconstruction ([Mathematical Formulation](MATHEMATICAL_FORMULATION.md#44-conservative-to-primitive-variable-inversion-formulation)).
- Solenoidal Magnetic Constraint Enforcement: `ConstrainedTransport2D` (`include/relativistic/hydro/solvers/constrained_transport.hpp`) maintains staggered face-centered magnetic fields ($B_{x,\text{face}}, B_{y,\text{face}}$) on $(n_x + 1) \times n_y$ and $n_x \times (n_y + 1)$ grids, evaluates vertex electric fields $E_{z, i+1/2, j+1/2} = -\frac{1}{4}\sum(v_x B_y - v_y B_x)$, advances face inductions via discrete curls, averages magnetic components to cell centers, and preserves $\nabla \cdot \mathbf{B} = 0$ to machine precision ([Mathematical Formulation](MATHEMATICAL_FORMULATION.md#47-constrained-transport-ct--solenoidal-magnetic-constraint)).
- One-Dimensional Relativistic Fluid Engine: `RelativisticHydroSolver1D` (`include/relativistic/hydro/solvers/grhd_solver.hpp`) evaluates 1D grid evolutions of $n_x$ cells with 3 ghost cells on each boundary, Outflow, Periodic, and Reflecting boundary conditions ($v_x \leftarrow -v_x$), acoustic CFL timestep regulation $\Delta t = \text{CFL} \cdot \Delta x / \max_i (|v_{x,i}| + c_{s,i}) / (1 + |v_{x,i}| c_{s,i})$, and third-order Strong Stability Preserving Runge-Kutta (SSP-RK3) temporal advancement, with automated setup for relativistic Sod shock tubes and Balsara-1 MHD shock tubes ([Description](DESCRIPTION.md#61-curved-spacetime-hydrodynamics)).
- Relativistic Stellar Structure & Hydrostatic Equilibrium: `TOVSolver` (`include/relativistic/hydro/solvers/tov_solver.hpp`) integrates the coupled Tolman-Oppenheimer-Volkoff system $(dm/dr, dm_b/dr, dp/dr, d\Phi/dr)$ using 4th-order Runge-Kutta stepping with origin quadratic Taylor series initialization, adaptive pressure scale-height regulation $\Delta r_{\text{opt}} = \operatorname{clamp}(0.05 h_p, \Delta r_{\min}, \Delta r_{\max})$, sub-step linear interpolation at the stellar surface $p \le 0$, and exterior Schwarzschild metric potential matching $\Phi(R) = \frac{1}{2}\ln(1 - 2GM/(c^2 R))$, evaluating gravitational mass $M$, baryonic mass $M_b$, compactness $C$, surface redshift $z_s$, central redshift $z_c$, and complete mass-radius equilibrium sequences $M(R)$ with radial stability boundaries $\partial M / \partial \rho_c \le 0$ and $1.4 M_\odot$ radius interpolation ([MATHEMATICAL_FORMULATION.md Section 4.8](MATHEMATICAL_FORMULATION.md#48-tolman-oppenheimer-volkoff-tov-stellar-structure--redshift-formulation)).
- Multi-Regime Equations of State: `IdealGasEOS`, `SyngeEOS`, `MathewsEOS`, `RelativisticFermiGasEOS`, `PolytropicEOS`, `PiecewisePolytropicEOS`, and `TabulatedNuclearEOS` (`include/relativistic/hydro/eos.hpp`) model fluid thermodynamics across ideal, kinetic, degenerate, and dense nuclear regimes, supporting analytical enthalpy and sound speed evaluations, low-$x$ kinetic energy density expansions ($x < 0.05$), Newton-Raphson density-from-pressure inversions ($dp/dx = 8 p_0 x^4 / \sqrt{1 + x^2}$), multi-piece enthalpy continuity constants $a_i$, 3D trilinear table interpolations over $(\log_{10}\rho, \log_{10}T, Y_e)$ across 5 nuclear presets (SFHo, Shen, LS220, SLy4, APR4), and HDF5 container serialization ([MATHEMATICAL_FORMULATION.md Section 4.9](MATHEMATICAL_FORMULATION.md#49-relativistic-equations-of-state-eos-formulations) and [FILE_FORMATS.md Section 3.2](FILE_FORMATS.md#32-standard-group-hierarchy)).
- Accretion Systems & Force-Free Magnetospheres: `NovikovThorneDisk` (`include/relativistic/hydro/novikov_thorne.hpp`, [MATHEMATICAL_FORMULATION.md Section 5.1](MATHEMATICAL_FORMULATION.md#51-novikov-thorne-thin-disk-profile)) integrates Page-Thorne analytical flux distributions around Kerr black holes; `FishboneMoncriefTorus` (`include/relativistic/hydro/fishbone_moncrief.hpp`, [Section 5.2](MATHEMATICAL_FORMULATION.md#52-fishbone-moncrief-magnetized-thick-torus)) evaluates stationary barotropic thick tori with constant specific angular momentum $l$; `BlandfordZnajekModel` (`include/relativistic/magnetosphere/blandford_znajek.hpp`, [Section 5.3](MATHEMATICAL_FORMULATION.md#53-blandford-znajek-jet-magnetosphere)) models horizon-threading force-free jet magnetospheres with Znajek boundary conditions.

### 2.7. Polarized Radiative Transfer & Optics

- Polarimetric Representation: `StokesVector` (`include/relativistic/optics/stokes_vector.hpp`), `StokesEmissivity`, and `StokesTransferMatrix` represent full-Stokes polarized transport with linear/circular/total polarization intensities, DoLP, DoCP, DoP, EVPA, and Mueller reference frame rotations ([MATHEMATICAL_FORMULATION.md Section 6.2](MATHEMATICAL_FORMULATION.md#62-full-stokes-polarized-representation--polarimetric-invariants)).
- Radiative Processes: `RadiativeProcessEngine` (`include/relativistic/optics/radiative_processes.hpp`) computes non-thermal synchrotron emission/absorption, thermal synchrotron with Faraday rotation ($\rho_V$) and conversion ($\rho_Q$), and relativistic Bremsstrahlung with thermal Gaunt factor corrections ([MATHEMATICAL_FORMULATION.md Section 6.4](MATHEMATICAL_FORMULATION.md#64-radiative-processes--coefficients)).
- Polarized Solver: `PolarizedRadiativeTransfer` (`include/relativistic/optics/polarized_radiative_transfer.hpp`) executes analytical matrix exponential integration along ray segments via Delano's scaling and squaring method with 12th-order Taylor series expansions of $\Psi(A)$, RK4 fallbacks, relativistic frequency shift scaling ($g^2$ emissivity and $g^{-1}$ transfer matrix scaling), and hybrid plasma integration ([MATHEMATICAL_FORMULATION.md Section 6.3](MATHEMATICAL_FORMULATION.md#63-polarized-transfer-system--delano-matrix-exponential-integration)).
- Polarized Spectral Synthesis: `PolarizedSpectrumSynthesizer` (`include/relativistic/optics/polarization_spectrum.hpp`) synthesizes polarized multi-wavelength spectra across non-thermal, thermal, and hybrid models, evaluating polarization summaries, EVPA rotation measure (RM) fitting, and spectral index fitting.
- Kinetic Models: `MaxwellJuttnerDistribution` (`include/relativistic/optics/maxwell_juttner.hpp`) samples thermal relativistic electron distributions via a 4-regime decomposition algorithm with rational Bessel approximations; `InverseComptonEngine` (`include/relativistic/optics/inverse_compton.hpp`) performs Monte Carlo photon packet scatterings via the Klein-Nishina differential cross section and evaluates Compton $y$-parameters ([MATHEMATICAL_FORMULATION.md Section 6.5](MATHEMATICAL_FORMULATION.md#65-maxwell-jüttner-relativistic-thermal-distribution) and [Section 6.6](MATHEMATICAL_FORMULATION.md#66-inverse-compton-scattering--klein-nishina-cross-section)).

### 2.9. Render Pipeline

**`GeodesicComputePipeline`** (`include/relativistic/render/geodesic_compute_pipeline.hpp`) owns a front and a back framebuffer of `GpuPixelOutput`. In windowed mode a worker thread renders the most recent pending request (`GpuCameraPushConstants` and body list); a request arriving while a frame is rendering raises a cancellation flag, so superseded frames are abandoned. In headless mode `dispatch` renders synchronously. After each frame the pipeline classifies pixels (horizon absorbed, celestial escape, accretion disk hit, step saturated), computes iteration statistics and records tile statistics of the adaptive sky prepass.

**Path selection.** When the distributed compute extension is bound and operational (`is_cluster_active`), frame rendering delegates eligible tile workloads across connected worker nodes via `dispatch_distributed`. In standalone mode, or when uncompleted tiles are reclaimed via work stealing, the Vulkan path is attempted when GPU compute is enabled and the executor is ready, and all of the following hold:

- The body count does not exceed 512.
- The precision mode is native FP64.
- The metric identifier is FlatMinkowski, Schwarzschild, Kerr, ReissnerNordstrom, KerrNewman or SchwarzschildDeSitter.
- Interlacing is disabled.
- No body requires the exact metric path (`SoftwareComputeEngine::requires_exact_metric_path`).

Otherwise `SoftwareComputeEngine::dispatch_fp64` or `dispatch_double_single` renders on the CPU thread pool, with the precision taken from the custom parameter `precision_mode`. Capture rendering uses the same selection through `render_capture` and `render_capture_band`.

**Vulkan execution** (`include/relativistic/render/vulkan_context.hpp`, `include/relativistic/render/vulkan_compute_executor.hpp`).

- Device selection requires a compute queue and `scalarBlockLayout`, and `shaderFloat64` when FP64 is requested. The score favors discrete GPUs, vendor identifier 0x10DE and FP64 support. When no device qualifies, the context stays initialized without a compute device and the CPU path is used.
- The shader `shaders/geodesic_tracer_fp64.comp.spv` is searched in `shaders`, `../shaders`, `./shaders` and `../../shaders`. CMake compiles it with `glslangValidator` when available.
- Descriptor bindings: 0 camera uniform buffer, 1 output storage buffer, 2 body storage buffer (`GpuBodyGpuLayout`), 3 panorama combined image sampler, 4 persistent counter storage buffer.
- Frames are dispatched in bands whose row count is a multiple of 16, limited to 64 MiB of output, and adapted toward 120 ms per band; cancellation is checked between bands.
- A fence timeout of 10 s (3 s for panorama uploads) marks the device as lost; GPU compute is then disabled and the CPU renderer is used for subsequent frames.
- When `sky_background_source` is not zero, the selected panorama (`SkyPanoramaLoader`) is uploaded as an `R8G8B8A8_SRGB` image.

**Viewport frame logic** (`ViewportPrimaryWindow`, `include/relativistic/ui/viewport_primary_window.hpp`).

- The internal resolution is the content size multiplied by the active scale, clamped to 64 to 3840 by 64 to 2160 pixels. The active scale is the resolution scale, replaced during navigation by the motion quality setting (disabled, automatic at 0.65 times the base scale, or fixed), and multiplied by the dynamic resolution factor (between 0.25 and 1.0, reduced by 6 % when the last frame exceeds 108 % of the target frame time and increased by 3 % when it is below 82 %).
- A new dispatch occurs only when the camera constants, the orchestrator state version, the precision selection or the advancing simulation time change.
- Bodies are culled by escape radius and, for perspective projections without lensing, by the view cone.
- Post-processing (contrast, saturation, lift, gamma, gain, highlights, shadows, vignette) is applied on the CPU before upload to an `RGBA32F` texture.
- The 3D body lighting system (`BodyLighting`, `include/relativistic/render/bodies/body_lighting.hpp`) evaluates one of 7 selectable light source modes: CentralSource (0, fixed at coordinate origin $(0, 0, 0)$), CameraHeadlight (1, co-located with the observer's spatial position $\mathbf{x}_{\text{obs}}$), FixedDirection (2, distant celestial key light with spherical horizontal azimuth $\phi_L \in [-180^\circ, 180^\circ]$ and vertical elevation $\theta_L \in [-90^\circ, 90^\circ]$), FixedPoint (3, localized point light source at Cartesian coordinates $\mathbf{x}_{\text{light}}$), NearestEmissiveBody (4, dynamic nearest-neighbor emitter search across active bodies where $I_{\text{em}} > 10^{-3}$, modulated by the emitter's primary color), SpecificBody (5, assigned emitting catalog body $B_{\text{id}}$ with primary color modulation), and Unlit (6, uniform unit diffuse shading without direct lighting, attenuation, or shadow calculations). Illuminance supports inverse-square distance attenuation $\mathcal{E}(d) = I_{\text{light}} \min((d_{\text{ref}}/d)^2, 64.0)$ under `LightAttenuationMode::InverseSquare`, terminator transition softness width $s \in [0, 1]$ via wrapped diffuse shading $D(s) = \operatorname{clamp}((\mu + s)/(1 + s), 0, 1)$ with smooth quintic/cubic twilight blending on planetary textures, Blinn-Phong specular reflections with microfacet roughness exponents $n_{\text{spec}} = 4 + 80(1 - \varrho)$, inter-body shadow occlusion rays tested against body bounding ellipsoids and central horizon spheres, and multi-source inter-body emission lighting accumulating radiant flux from active emitters with inverse-square falloff clamped to $16.0\times$ maximum gain ([MATHEMATICAL_FORMULATION.md Section 8.4](MATHEMATICAL_FORMULATION.md#84-celestial-body-shading)). Execution detail is regulated across three quality presets (`Minimal`, `Reduced`, `Full`), with configurable integer caps on tested shadow occluders (`body_shadow_caster_limit`, 1 to 512) and active radiant emitters (`body_emission_source_limit`, 1 to 512). Six standardized scene lighting presets (`Stellar Default`, `Headlight`, `Studio Key`, `Unlit`, `Dramatic`, `Reset`) provide repeatable illumination configurations across CPU and GPU pipelines.
- Procedural multi-layer celestial skybox generation (`SkyboxRenderer`, `include/relativistic/render/skybox_renderer.hpp`) evaluates equal-area spherical voxel partitioning ($N_{\text{grid}} \approx 14\sqrt{\rho_{\text{stars}} Q_{\text{eff}}}$) and 8 analytical star point spread functions (Gaussian, Lorentzian, Moffat, Airy diffraction with rational Chebyshev Bessel $J_1(x)$ polynomial approximation, HardDisc, DiffractionSpikes with configurable 4/6/8 spikes, PinpointDirac with concentration control, and CinematicBloom with secondary wide-angle exponential halos), 6 star placement density laws (UniformEqualArea, GalacticDisk, FractalClustered, DualPopulation, SpiralArmDensity, ConstellationAssociations), 4 parameter sampling distributions (Uniform, PowerLaw/Pareto, Exponential, LogNormal), blackbody chromaticity lookup via Wien displacement temperature intervals, multi-layer FBM nebulae with divergence-free 3D curl-noise advection, ionization emission, and gas contrast exponents, open and globular star clusters with Plummer density profiles and member star sampling via cumulative mass inversion, fractal interstellar dust extinction lanes via Beer-Lambert absorption, deep-field background galaxies across 6 morphologies (Grand Design, Flocculent, Barred, Elliptical with de Vaucouleurs Sersic radial profiles, Lenticular, Ring) with inclined dust extinction, quasars with collimated relativistic jets and Doppler boosting ($\delta^3$), pulsars with rotating magnetic dipole sweep beams and wind nebulae, supernova remnant shells with filamentary turbulence and reverse-shock interior glow, and a 3D spherical coordinate grid with major/minor lines, degree ticks, polar singularity tapering $\kappa_{\text{pole}}$, and 5 cell fill modes (None, Checkerboard2Color, CyclicPalette, CheckerboardPattern, RandomHashFill) indexing an editable 16-color palette ([MATHEMATICAL_FORMULATION.md Section 12](MATHEMATICAL_FORMULATION.md#12-procedural-skybox-mathematics)). Environment settings are encapsulated in the 1808-byte `GpuSkyProfile` uniform structure transferred to the GPU compute shaders. A dedicated Skybox & Environment Editor window provides real-time control over all parameters.
- 3D body surface texturing evaluates 27 distinct modes: 13 procedural shaders (Noise, Solid, Palette, BandedGas, Cratered, Stellar, Accretion, Marbled, RingedGas, Ice, Magma, CityLights, NebulousCloud) and 14 imported photographic textures (Earth Blue Marble, Sun Photosphere, Mercury Cratered, Venus Atmosphere, Venus Radar Altimetry, Mars Basalt & Deserts, Jupiter Zonal Belts, Saturn Cloud Belts, Uranus Methane, Neptune Vortex, Ceres Regolith, Eris Ice, Haumea Crystalline, Makemake Tholins). Photographic Earth textures support 1K/2K resolution and Day, Night, or Automatic day/night blending with smooth twilight terminator softness.
- Accretion rendering supports three selectable physical models: geometrically thin procedural disks, relativistic Novikov-Thorne thin disks with Page-Thorne analytical flux integration, and volumetric Fishbone-Moncrief thick magnetohydrodynamic tori in barotropic equilibrium ([MATHEMATICAL_FORMULATION.md Section 5](MATHEMATICAL_FORMULATION.md#5-accretion-disk-physics)). Horizon-threading Blandford-Znajek magnetosphere jets model force-free poloidal stream functions, Znajek horizon currents, and synchrotron emission ([Section 5.3](MATHEMATICAL_FORMULATION.md#53-blandford-znajek-jet-magnetosphere)).
- Multi-Source Kerr Black Hole Execution: For spacetimes containing multiple independent black holes (`preset_3d == 8`), execution routes to superposed Kerr-Schild null geodesic integration ($g_{\mu\nu} = \eta_{\mu\nu} + 2 \sum_i H_i k_\mu^{(i)} k_\nu^{(i)}$). On GPU (`geodesic_tracer_fp64.comp`), workgroup thread 0 compiles up to 16 horizon centroids, masses, spins, orientation triads, and accretion disk boundaries into workgroup shared memory (`ms_position_mass`, `ms_axis_spin`, `ms_frame_x_horizon`, `ms_frame_y_equatorial`, `ms_disk_range`, `ms_body_slot`) followed by `memoryBarrierShared(); barrier();`. All workgroup threads then execute `trace_multi_source` in native FP64 without CPU readback. On CPU, `SoftwareComputeEngine` populates `MultiSourceData` and executes `trace_multi_source`. Both paths evaluate Hamiltonian null geodesic equations of motion driven by analytical gradients $\nabla H_i$ and $\nabla(\mathbf{k}^{(i)} \cdot \mathbf{p})$ (`ks_source_terms`), observer tetrad lifting via Gram-Schmidt orthonormalization in the superposed metric (`ms_initial_momentum`), simultaneous analytical oblate horizon entry resolution (`ms_horizon_entry`), and local accretion disk crossings (`ms_disk_crossing`) ([MATHEMATICAL_FORMULATION.md Section 1.3](MATHEMATICAL_FORMULATION.md#13-kerr-metric-rotating-black-hole)).
- In schematic mode the ray tracing dispatch is skipped ([Section 2.12](#212-schematic-view-and-hud)).

### 2.10. Capture Subsystem

**Coordinator.** `CaptureCoordinator` (`include/relativistic/capture/capture_coordinator.hpp`) manages one capture session at a time. `update(dt)` is called once per UI frame and prepares frames; a worker thread executes the queued tasks (frame rendering, file writing, ffmpeg assembly). The capture constants are derived from the last constants dispatched by the viewport, with the current camera, exposure and mass parameters substituted (`ViewportPrimaryWindow::build_capture_constants`).

**Frame rendering.**

- The output is rendered in horizontal bands of `clamp(2^21 / (width * k^2), 1, height)` rows, where `k` is the supersampling factor. Each band is traced at $k$ times the output resolution through `GeodesicComputePipeline::render_capture_band` and streamed to an `ImageStreamWriter`, so memory use does not depend on the output height. When cluster compute offload is active, `record_cluster_stages` logs network tile dispatch and decompression timings (`ClusterNetworkDispatch`, `ClusterTileDecompress`) to the profiler.
- Supersampling and temporal samples are averaged in linear light using lookup tables for sRGB decoding (4096 entries) and encoding (16384 entries). A fade factor scales the result.
- Capture constants disable interlacing, the level-of-detail flag and the adaptive tile prepass, optionally replace the step budget, and divide `step_size_factor`, `min_step_size` and `max_step_size` by the step refinement factor.
- Render Overrides: Capture targets support dedicated overrides for layer visibility (Live, Hide All Bodies, Bodies Only), body detail tier (Live, High Detail, Maximum Detail), accretion disk suppression, projection overrides (Pinhole, Fisheye, 360, Panini, Hammer-Aitoff), HDR tonemapper overrides, FOV override, exposure offset, viewport post-processing color grading (`ColorGrade`), and 8-bit triangular dither strength (`triangular_noise`) preventing quantization banding ([Section 9.5](MATHEMATICAL_FORMULATION.md#95-capture-frame-post-processing--triangular-noise-dithering)).
- Output Resolution: Supports explicit pixel dimensions or viewport multipliers ($0.1\times$ to $16.0\times$); 19 standard resolution presets (720p, 1080p, 1440p, 4K, 5K, 8K, 16K, Square 2K/4K/8K, Vertical 1080p/4K, Ultrawide 1080p/1440p, Cinema 2K/4K, 360 4K/8K/16K) with aspect ratio locking and viewport size/aspect matching.
- Limits: 65535 pixels per output axis, 262144 per traced axis, supersampling at most 8.

**Deterministic mode.** For each frame the coordinator processes script events, then for each of the `temporal_samples` sub-frame times: advances the simulation (`ticks_per_frame` multiplied by the script simulation rate and divided by the sample count, accumulated as a fractional tick count), applies the script pose (resolved against `CameraCollisionField` when camera collision is enabled), and stores constants and bodies. The shutter offsets are centered on the frame time, span `shutter_fraction` of the frame interval, and incorporate `shutter_phase` shifts in $[-1.0, 1.0]$. At most two frames are queued at once (`kMaxQueuedFrames = 2`). World advance modes: frozen, fixed ticks per frame, or simulation seconds per video second (ticks per frame = `s / (fps * tick_dt)`). With the trigger `PathDuration`, the frame index is mapped linearly onto the script duration. Continuous parameter and warp ramps are evaluated at each sub-step by `ScriptEventDispatcher`. Pause and resume events freeze and release the world. Manual stepping renders one frame per request (at most 64 pending). The live viewport render is suppressed unless `preview_in_viewport` is set.

**Real-time mode.** The front framebuffer is copied at the frame interval. Pacing either drops late frames or duplicates the last frame to fill gaps; frames waiting for disk writing are limited by the queue depth. The viewport resolution multiplier is locked, and frames whose size changes are resampled by nearest neighbor to the first frame size. Real-time post-processing applies the color grade and triangular dither directly before disk queuing.

**Session end.** The recorder is finalized, the camera, field of view, exposure, camera mode, warp factor and pause state are restored (the camera only when `restore_camera_after_capture` is set or a script was used), `sequence_info.txt` is written (documenting execution mode, submitted/written/dropped/duplicated frames, camera collision state, recording path, resolution, and assembly command), `motion_script.cfg` is archived, and ffmpeg is invoked through `std::system` when assembly is enabled and the session completed. Output files are described in [FILE_FORMATS.md](FILE_FORMATS.md#7-capture-session-directory).

**Motion script** (`include/relativistic/capture/motion_script.hpp`). A script is an ordered list of segments with a global easing and an end behavior (clamp, loop, ping-pong).

- Segment: duration, time easing, anchor (world, continue previous, offset from previous, track body), shape layers, orientation, scalar channels (field of view, exposure, roll, simulation warp), shake, segment-level projection mode assignment (`projection_mode`), and a transition blending from the previous segment (orientation, position, lens, and projection mode transitions).
- Shape layers: 29 shape kinds organized into seven categories:
  - Basic: Hold, Linear, QuadraticBezier, CubicBezier.
  - Waypoints: Spline (Catmull-Rom), Polyline, BSpline (uniform cubic), with waypoint coordinate tables, add-from-camera buttons, duplication, subdivision, reverse, closed loop, and uniform speed parameterization.
  - Rotations: Arc, Helix, Orbit, LogarithmicSpiral, ArchimedeanSpiral.
  - Closed Curves: Lissajous, TorusKnot, Lemniscate, Rose, Epitrochoid, Wave.
  - Equations: ExpressionCartesian ($x(u), y(u), z(u)$), ExpressionCylindrical ($r(u), \theta(u), z(u)$), ExpressionSpherical ($r(u), \theta(u), \phi(u)$) evaluated over variables ($t, u, d, g, a, b, c, k$).
  - Surface & Body Orbit: SurfaceWalk, SurfaceLoop, SurfaceRoute, PlanetOrbit. Automatically conforms trajectories to deformed triaxial body ellipsoid dimensions ($R_x, R_y, R_z$) with eye height and altitude ratios.
  - Relativistic & Dynamic Trajectories: FreeFallInfall (geodesic plunge with radial contraction, accelerated azimuthal progress, and Lense-Thirring spin drag around spinning black holes), ConicalHelix (conical/polar jet helix with axial power-law acceleration, radius expansion, and pinch modulation), KeplerianOrbit (Keplerian elliptical orbit with Newton-Raphson eccentric anomaly solving and 3D orbital plane Euler orientation), and DynamicChase (smooth pursuit camera with comoving velocity-aligned frame, second-order harmonic damping response filtering, and velocity lead anticipation). Formulations are detailed in [MATHEMATICAL_FORMULATION.md Section 9.2](MATHEMATICAL_FORMULATION.md#92-position-curves).
  - Layer blending: Replace, Add, Add Relative To Layer Start (for stacking procedural noise or secondary oscillations onto a primary path) inside a progress window $[w_0, w_1]$, with an affine transform (scale, Euler rotation, pivot, translation).
- Orientation modes: Free, Fixed, Interpolated (with easing), Look At Target (with Nearest Body support), Along Travel Direction (with look-ahead progress factor), Expressions, Target Path (moving target along separate trajectory), Surface Walker (stays upright relative to body normal and faces travel heading), and Chase Lead (orients toward anticipated target position using velocity lead time $\tau_{\text{lead}}$).
- Scalar channels: start and end values with easing, expression override ($t, u, d, g, r, x, y, z, v, p, s, a, b, m$), periodic wave modulation (sine, triangle, square, sawtooth, noise with start/end amplitude, frequency, phase, and edge fade), and reactive drivers.
- Reactive Drivers (`DriverSpec`): Maps live measurements onto channel values via 12 signal sources (Distance to Target, Distance to Origin, Position X/Y/Z, Camera Speed, Segment/Script Progress, Segment/Script Time, Event Time Offset, Custom Expression), configurable input/output bounds, response easing, and blend modes (Replace, Add, Multiply).
- Transitions: Evaluates independent blend durations and easing curves for view orientation (Shortest Arc vs Direct Interpolation), position, lens/rate, and optical projection mode. Projection transitions evaluate across seven modes (`ProjectionTransitionMode`: StepAtMidpoint, StepAtStart, StepAtEnd, SmoothMorph, FovCompensatedMorph, CrossZoom, WarpCurvature) with projection blend factor and FOV compensation ([MATHEMATICAL_FORMULATION.md Section 9.4](MATHEMATICAL_FORMULATION.md#94-projection-mode-transitions--morphing-mathematics)).
- Easing: 46 kinds (linear, quadratic to quintic, sinusoidal, exponential, circular, back, elastic and bounce families in in, out and in-out variants, smoothstep variants, power, steps, delay window, cubic Bezier, damped spring, custom expression, custom curve, sigmoid, curvature, smooth steps, wobble) with blend, repeat, ping-pong, reversal, input and output windows, bias, gain and quantization.
- Events: four triggers (script time, segment start, segment end, segment fraction with time offsets) and 15 actions (Marker, CaptureStill, SetParameter, SetWarp, Pause, Resume, StepTicks, SetMetric, SetIntegrator, LoadScenario, SetTickRate, SetPerformancePreset, SetOverlay, SetResolutionScale, SetProjectionMode). Parameter, warp, tick rate, resolution scale, and projection mode events support transition ramps with configurable easing curves across 52 mapped parameter types ([FILE_FORMATS.md Section 9](FILE_FORMATS.md#9-motion-script-and-capture-settings-files)).
- Presets: Orbit Reveal, Spiral Infall, Fly-By With Stop, Dolly Zoom, Figure Eight Survey, Helical Approach, Torus Knot Showcase, Multi-Stage Tour, Photon Sphere Skim, Handheld Drift, Planetary Stroll, Planet Orbit Survey, Relativistic Infall Plunge, Polar Jet Helical Ascent, Keplerian Gravitational Slingshot, and N-Body Pursuit Camera.

**Expression language** (`include/relativistic/capture/expression.hpp`). Expressions compile to a stack program. Variables: `t` (segment time), `u` (progress), `d` (duration), `g` (script time), `a`, `b`, `c`, `k` (parameters), `r` (radius), `x`, `y`, `z` (position), `v` (speed), `m` (driven measurement), `p` (script progress), `s` (segment index). Constants: `pi`, `tau`, `e`. Operators: `+ - * / % ^`, `< > <= >= == !=`. Functions: `sin cos tan asin acos atan sinh cosh tanh exp log ln log2 log10 sqrt cbrt abs floor ceil round fract sign rad deg saturate smooth noise tri saw square atan2 min max hypot step pow mod clamp mix if smoothstep`. Division by zero evaluates to 0 and non-finite results are replaced by 0.

**Recording and preview.** `PhysicsRecorder` derives kinematic and relativistic channels from the live camera pose and the orchestrator state for each frame ([FILE_FORMATS.md](FILE_FORMATS.md#8-telemetry-recording-files)). `build_path_preview` (`include/relativistic/capture/path_preview_builder.hpp`) samples the script into a `PathPreview` (vertices, reference path without shake and transitions, markers, camera frustum) drawn by the schematic renderer.

### 2.11. Profiling, Logging and Persistence

**`PerformanceProfiler`** (`include/relativistic/orchestrator/performance_profiler.hpp`) keeps a ring of `FrameSample` records (default capacity 3600, minimum 16). Stage durations are accumulated through `ScopedStageTimer` and attached to the next recorded frame. The stages are FrameTotal, RenderDispatch, TextureUpload, HudOverlay, CameraUpdate, SchematicOverlay, PostProcessing, FramebufferReadback, GpuDispatchExecution, CpuDispatchExecution, AdaptiveTilePrepassSky, PixelClassification and CameraConstantsBuild.

- `StatisticalSummary` provides mean, median, minimum, maximum, population standard deviation and the 95th and 99th percentiles (linear interpolation).
- `analyze_bottleneck` selects the dominant stage among all stages except FrameTotal and the five render sub-stages, reports ray step saturation when the mean saturated ray fraction exceeds 0.35, and flags a window without any GPU frame.
- Benchmark runs are captured over a duration or a frame count, store the configuration of the last captured frame together with the statistics, and are persisted ([FILE_FORMATS.md](FILE_FORMATS.md#102-configperformance_profilercfg)).

### 2.14. Distributed Compute Subsystem & Heterogeneous Cluster Architecture

The distributed compute subsystem extends the execution capabilities of the engine without modifying its single-node determinism or introducing heap allocations in inner computational loops:
- Offline Autonomy: Network sockets, worker threads, and communication buffers remain uninstantiated when `cluster.enabled = 0`. Local execution performance on Vulkan FP64 or CPU SIMD remains identical to non-distributed builds.
- Cluster Node Roles: Instances operate as `ClusterMaster` (interactive host or headless batch coordinator), `ComputeWorker` (autonomous lightweight worker `cluster_worker` without graphical dependencies), `HybridNode` (co-evaluating local and remote partitions), or `Standalone` (isolated single-machine execution).
- Worker Lifecycle State Machine: Remote nodes progress through seven finite states: `Unauthenticated`, `Handshaking`, `Synchronized`, `Ready`, `Computing`, `Stalled`, and `Disconnected`. Transitions are strictly enforced by `is_valid_node_transition`. Stalled nodes automatically trigger work-stealing reclamation.
- Transport Dual-Channel Multiplexing: The transport layer utilizes ENet/UDP over two logical channels:
  - Channel 0: Sequenced reliable control channel handling authentication handshakes, clock synchronizations, catalog chunk broadcasts, and frame cancellation messages.
  - Channel 1: Unsequenced, unreliable-fragmented data channel for tile workloads and return datagrams up to $256\,\text{KiB}$, preventing head-of-line blocking across independent image tiles.
- Cryptographic Channel (`CryptoChannel`): All datagrams enforce AEAD encapsulation using ephemeral X25519 Diffie-Hellman key exchange, HKDF-SHA256 key derivation with `"RelativisticEngineV1"` domain separation, and ChaCha20-Poly1305 authenticated symmetric encryption with a 64-packet anti-replay sliding window. Every packet begins with a 48-byte aligned `PacketEnvelope` (`0x52454C44` magic identifier, 28-byte authenticated header as AAD, and 16-byte Poly1305 MAC tag; [FILE_FORMATS.md Section 11.1](FILE_FORMATS.md#111-network-transport-framing-and-packet-envelope-structure)).
- Distributed Compute Task Offloading: The orchestrator routes five classes of parallel jobs:
  1. *Interactive Viewport Screen Tiles*: $32 \times 32$ pixel work units mapped via `resolve_tile_geometry` ($N_{\text{cols}} = \lceil W / 32 \rceil, N_{\text{rows}} = \lceil H / 32 \rceil$), evaluated via Vulkan compute (`cluster_tile_tracer_fp64.comp`) or multi-threaded CPU SIMD (`TileRenderer`).
  2. *Capture Studio Image Bands*: Horizontal scanline bands streamed directly to disk writers, bypassing full frame allocations.
  3. *Post-Newtonian N-Body Row Blocks*: Row-partitioned pairwise acceleration matrix reductions evaluated via `GpuNBodyExecutor` executing `nbody_accel_fp64.comp` in FP64 on Vulkan or CPU `evaluate_nbody_accelerations_local` across Newtonian and 1PN/2.5PN phases.
  4. *Monte Carlo Geodesic Ensembles*: Photon packet bunches with online moment reduction via the Chan-Golub-LeVeque algorithm (`run_geodesic_ensemble_local`).
  5. *Generalized Polynomial Chaos Quadratures*: Multi-dimensional stochastic quadrature evaluations (`run_stochastic_pce_quadrature_local`).
- Slurm HPC Integration: `SlurmInterface` detects MPI rank and task allocation (`SLURM_PROCID`, `SLURM_NTASKS`, `SLURM_STEP_NODELIST`). Rank 0 configures and starts `ClusterOrchestrator` with local GPU compute offload, while higher ranks execute autonomous `ClusterWorkerService` daemons connecting back to rank 0.
- Compression Pipeline: Three selectable compression modes:
  - `DirectRaw`: Uncompressed raw 32-byte pixel output with zero CPU overhead for low-latency 10GbE LAN environments.
  - `QoiHdrRle`: Radiance quantization into IEEE 754 half-precision (FP16) floats with run-length encoding for flags and iteration counts.
  - `Lz4Block`: SIMD channel-shuffled block compression delivering $> 3.5\,\text{GB/s}$ decompression throughput.
- Data Sanitization: All remotely computed `GpuPixelOutput` payloads undergo explicit SIMD vector scanning guarding against NaNs, infinities, and unphysical negative radiances, clamping radiant flux to $[0.0, 1.0 \times 10^8]\,\text{W/m}^2/\text{sr}$.
- Discovery Service: Decentralized UDP multicast beacons on `239.255.77.88:42424` with CRC32 verification and cluster namespace hashing for zero-configuration LAN clustering.

## 3. Concurrency, Execution Pipeline & Scheduling

The system employs a multi-threaded execution model designed to eliminate synchronization stalls & lock contention:

### 3.1. Deterministic Simulation Scheduler

The execution flow is governed by `Scheduler`, maintaining a fixed logical clock frequency (10 to 1000 Hz) decoupled from visual presentation refresh rates:
- Nanosecond Accumulator: Real-time increments are buffered into a high-precision accumulator. Logical ticks advance when the accumulator exceeds the fixed step interval ($\Delta t = 1 / f_{\text{tick}}$).
- Step & Warp Control: The scheduler supports pause states, single-tick stepping (`request_steps`), & continuous time dilation scaling (`warp_factor`).
- Sub-Tick Interpolation: For visual smoothing, the scheduler exposes the fractional alpha factor $\alpha = t_{\text{accum}} / \Delta t_{\text{tick}} \in [0, 1]$.
- Initial State & Clamping: The scheduler starts paused at 60 Hz with a warp factor of 1. The accumulator is clamped to 0.25 s so that a long frame does not produce a burst of ticks. A requested step executes regardless of the accumulator, and the scheduler pauses when the requested step count reaches zero. Each tick advances the logical time by $\Delta t_{\text{tick}} \cdot w$, where $w$ is the warp factor.

### 3.2. Asynchronous Lock-Free Command Queue

Communication between the master terminal/UI & the simulation core is mediated by `SpscQueue` (Single-Producer Single-Consumer lock-free ring buffer):
- Memory Ordering: Atomic operations utilize explicit acquire-release semantics (`std::memory_order_acquire`, `std::memory_order_release`) with cache-line-isolated pointers (64-byte padding) to eliminate false sharing.
- Command Dispatch: Commands are processed synchronously at the boundary of each logical simulation cycle. Command execution results are pushed back to a dedicated lock-free result queue.

### 3.3. Thread Pool & Raytracing Work Distribution

- Persistent Thread Pool: `ThreadPool` manages a static pool of `std::jthread` workers synchronized via condition variables, executing chunked parallel loops (`parallel_for`).
- Spatial Tiling & SIMD Bundling: Raytracing passes support both horizontal scanline slicing & 2D spatial block tiling ($32 \times 32$ pixels). Ray bundles are evaluated using 4-wide or 8-wide SIMD registers.

### 3.4. Orchestrator State Advance

`SimulationOrchestrator::advance_simulation(dt)` (`include/relativistic/orchestrator/simulation_orchestrator.hpp`) performs the following steps:

1. The central body is synchronized: a body named `Central Object` of mass $M$, radius $2M$ and spin $(0, 0, aM)$ is registered as the spacetime source, unless an enabled body of mass above $0.5M$ already sits at the origin.
2. The interaction configuration is passed to the N-body system.
3. The N-body system is advanced. The step is divided into $\min(500, \lceil \Delta t / \Delta t_s \rceil)$ sub-steps with $\Delta t_s = 0.05 / \omega_{\max}$ and $\omega_{\max} = \sqrt{\max(M, 10^{-4}) / \max(r_{\min}^3, 10^{-6})}$, where $r_{\min}$ is the smallest radius of an enabled body. Each sub-step applies the symplectic Forest-Ruth post-Newtonian integrator when the integrator name contains `Symplectic` or `Gauss`, and the fourth-order Runge-Kutta post-Newtonian integrator otherwise, followed by the interaction step and the horizon absorption step. Bodies disabled before the step keep their state.
4. In the Rocket Thrust camera mode, the camera position is integrated with the camera velocity while the scheduler is not paused.
5. The state version counter is incremented. The user interface compares this counter to detect parameter changes and to trigger a re-render.

Horizon absorption and black hole merging (`handle_horizon_absorption`) operates on the central mass with spin clamped to $\pm 0.999M$ and outer horizon radius $r_h = M + \sqrt{M^2 - a^2}$:

- A regular body with $r \le 1.001 r_h$ is absorbed: its mass $m_b$ is added to the central mass ($M \leftarrow M + m_b$), and the body is disabled (`enabled = false`, `integrity = 0.0`).
- A spacetime source body within $r_h + r_{h,b}$ of the origin merges into the central object: orbital angular momentum $L_{\text{orb}} = m_b (x v_y - y v_x)$ is extracted, total angular momentum $J_{\text{tot}} = a M + S_z m_b + L_{\text{orb}}$ is accumulated, central mass advances to $M \leftarrow M + m_b$, central spin recomputed as $a \leftarrow \operatorname{clamp}(J_{\text{tot}} / M, -0.999M, 0.999M)$, and the source body is disabled.
- A regular body within $1.001$ times the horizon radius $r_{h, i}$ of an active subsidiary source body $i$ merges into it: mass advances to $M_i \leftarrow M_i + m_b$, velocity is momentum-weighted $\mathbf{v}_i \leftarrow (M_i \mathbf{v}_i + m_b \mathbf{v}_b) / (M_i + m_b)$, spin vector is additive $\mathbf{S}_i \leftarrow \mathbf{S}_i + \mathbf{S}_b$, charge is additive $Q_i \leftarrow Q_i + q_b$, and `enforce_spacetime_source_invariants` reclamps dimensionless spin parameter $a_{*, i} \in [-0.9999, 0.9999]$ and updates the horizon radius.
- Two subsidiary source bodies within $1.05 \max(r_{h, i}, r_{h, j})$ merge into the more massive survivor: mass $M \leftarrow M_i + M_j$, velocity momentum-weighted $\mathbf{v} \leftarrow (M_i \mathbf{v}_i + M_j \mathbf{v}_j) / (M_i + M_j)$, spin vector additive $\mathbf{S} \leftarrow \mathbf{S}_i + \mathbf{S}_j$, charge additive $Q \leftarrow Q_i + Q_j$, with invariant enforcement and recomputed horizon dimensions.
- When any absorption or merger occurs, the catalog is rebuilt without disabled bodies, pairwise accelerations are updated, the central body is resynchronized, and a forensic diagnostic milestone is recorded (`Core::Diagnostics::record_milestone`).

Command application, including the `Reset` semantics, is described in [CLI_REFERENCE.md](CLI_REFERENCE.md#25-command-processing-and-performance-presets). Changes to $c$ and $G$ in the constants engine are copied to the N-body configuration.

### 3.5. Scenario Resolution and Startup

`ScenarioLocator` (`include/relativistic/io/scenario_locator.hpp`) resolves files and the scenario directory relative to the working directory and up to four parent levels (`kMaxAncestorDepth`). A requested path is tried as given, then prefixed by up to four `..` components, then, when its parent directory is named `scenarios`, against the located scenario directory. `portable_path` stores paths inside the scenario directory in the form `scenarios/<file>`.

At startup `UiManager::queue_startup_scenario` loads the configured `default_scenario_path` when `load_scenario_on_startup` is set. If the file cannot be resolved, parsed or validated, the built-in `scenarios/schwarzschild_accretion.yaml` is loaded instead and becomes the stored startup path; when it is also unavailable, the simulation starts empty. The Scenario Manager scans the directory for `.yaml` and `.yml` files, marks files that fail parsing or validation as incompatible, protects the built-in startup file from deletion, and saves new presets under collision-free file and scenario names (`<stem>_<n>.yaml` and `<name> (<n>)`).

### 3.6. Distributed Workload Scheduling & Work Stealing

`DistributionScheduler` (`include/relativistic/distributed/distribution_scheduler.hpp`) partitions visual frames, post-Newtonian N-body systems, and stochastic ensembles:
- Tile Grid Partitioning: High-resolution viewports are partitioned into $32 \times 32$ pixel work units (`kTileEdgePixels = 32`). Initial integer quotas $K_i = \lfloor \Omega_i(t) \cdot N_{\text{active}} \rfloor$ conserve work by assigning remaining deficit tiles to the local node (`local_slot`). Quota distribution supports `Interleaved` mode (Bresenham-style credit accumulation distributing adjacent tiles across different nodes) and `Contiguous` mode (sequential tile block assignment).
- Dynamic Latency-Weighted Allocation: Normalized capacity shares $\Omega_i(t)$ are calculated per frame from static node weights $\omega_i$, rolling average ray execution throughputs $\overline{\Delta t_{\text{exec}, i}}$, and round-trip latencies $\text{RTT}_i$ ([MATHEMATICAL_FORMULATION.md Section 10.1](MATHEMATICAL_FORMULATION.md#101-latency-damped-capacity-share-formulation)).
- Work Stealing & Fault Recovery: Dispatched tiles track lifecycle states through `TileStatus` (`Skipped`, `Queued`, `InFlight`, `Reclaimed`, `CompletedRemote`, `CompletedLocal`). Tasks carry dynamic deadlines $t_{\text{deadline}} = t_{\text{dispatch}} + \operatorname{clamp}(\overline{\text{RTT}}_i + 3.5 \sigma_{\text{RTT}, i} + t_{\text{compute}, i}, t_{\min}, t_{\max})$. Work stealing operates across three triggers:
  1. `collect_expired`: Reclaims tiles whose deadlines have elapsed (`ReclaimReason::Timeout`).
  2. `steal_speculative`: Reclaims in-flight tiles when elapsed time exceeds a configurable fraction ($\text{speculative\_fraction} \in [0.05, 1.0]$, default 0.5) of the deadline window, sorted by earliest dispatch time (`ReclaimReason::Speculative`).
  3. `reclaim_node`: Immediately reclaims all in-flight tiles assigned to a disconnected or stalled node (`ReclaimReason::NodeLost`).
  Reclaimed tiles execute on the local thread pool (`should_compute_local`) and complete via atomic compare-and-swap (`try_complete_local`). Duplicate remote completions increment `late_results_discarded` telemetry without state corruption.

## 4. Precision Architecture & Numerical Stability

The engine provides multi-tiered precision configurations to balance numerical accuracy & throughput:

### 4.1. Hardware-Native 64-Bit Precision (FP64)

- Standard execution path using native IEEE 754 double precision (`double`) across all tensor algebra, Christoffel derivations, variational mechanics, & geodesic integration loops.
- Recommended for research trajectories, high-spin Kerr horizons, & multi-century post-Newtonian orbital baselines.

### 4.2. Compensated Double-Single Arithmetic (DS / fp32-fp32)

- `DoubleSingle` (`include/relativistic/render/double_single.hpp`) emulates extended precision (approx. 48 bits of mantissa, matching $\approx 14$ decimal digits) using pairs of IEEE 754 single-precision floats (`hi`, `lo`). The functions `ds_sin`, `ds_cos` and `ds_atan2` evaluate in `double` and split the result.
- Exact error-free transformations via Knuth's `two_sum`, Dekker's `two_diff`, and Veltkamp-Dekker `two_prod` (using hardware `fma`).
- Executed by `SoftwareComputeEngine::dispatch_double_single` on the CPU ([Technical Manual](TECHNICAL_MANUAL.md#29-rendering-back-ends)). The Vulkan compute path requires native FP64 and is skipped when double-single precision is selected (see [Section 2.9](#29-render-pipeline)).

### 4.3. SIMD Register Vectorization

- `SimdVec<T, Width>` and `SimdMask<T, Width>` (`include/relativistic/core/simd.hpp`) map to native SIMD registers across AVX2, AVX-512, and ARM Neon ([Technical Manual](TECHNICAL_MANUAL.md#21-static-tensor--simd-algebra-layer)).
- `GeodesicBundle` (`include/relativistic/core/geodesic_bundle.hpp`) formats ray coordinates and four-momenta in Structure-of-Arrays (SoA) layout, executing vectorized RK4 updates across concurrent ray lanes (`GeodesicBundle4d` and `GeodesicBundle8f`; see [TECHNICAL_MANUAL.md Section 2.9](TECHNICAL_MANUAL.md#29-rendering-back-ends)).
