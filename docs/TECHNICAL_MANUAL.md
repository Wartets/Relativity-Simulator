# Relativistic Engine - Technical Architecture Manual

## 1. Core Engineering & System Design

The Relativistic Engine is written in ISO C++23. It is structured around data-oriented memory layouts, static compile-time polymorphism, deterministic execution guarantees, & parallel computation.

### 1.1. Design Constraints

- Zero Dynamic Allocations in Execution Loops: Computational loops operate within pre-allocated linear memory arenas (`LinearMemoryArena`) aligned to 64-byte and 128-byte cache boundaries. The per-ray integration loops of `SoftwareComputeEngine` do not allocate. Frame-level data of the render and capture pipelines (framebuffers, body lists, tile-culling tables, texture upload buffers) are `std::vector` objects resized on demand (see [ARCHITECTURE.md](ARCHITECTURE.md#29-render-pipeline)).
- Concept-Driven Polymorphism: Virtual method dispatch is replaced by C++23 concepts (`SpacetimeMetric`) and templates to enable compile-time inlining of metric and equation of state routines.
- Strict Numerical Determinism: Trajectory calculations, N-body evolutions, & stochastic sampling use explicit-state PCG64 generators (`PCG64Engine`). Floating-point arithmetic rounding behavior is preserved to maintain identical results across runs. Procedural sky and body surface patterns are integer hash functions of the ray direction or surface coordinates and a user-controlled seed. Randomized body creation in `BodyManagerWindow` uses `std::mt19937_64` seeded from `std::random_device` and is not reproducible.
- Continuous Multi-Paradigm Uncertainty: Variables support uncertainty tracking via interval bounds (IEEE 1788), order-reduced zonotopes, Jacobi-Lyapunov covariance matrices, & generalized polynomial chaos expansions (gPCE).

## 2. Core Subsystems & Components

### 2.1. Static Tensor & SIMD Algebra Layer

- `Tensor<T, Rank, Dim>`: Cache-aligned multidimensional tensor container supporting compile-time rank & dimension validation, outer products, Einstein summation contractions, metric inversions, & determinants.
- `SimdVec<T, Width>` & `SimdMask<T, Width>`: Register-width SIMD abstraction wrappers providing vector arithmetic, conditional blending (`select`), fused multiply-add (`fma`), & trigonometric evaluations.
- `GeodesicBundle<T, Width>`: Structure-of-Arrays (SoA) layout executing parallel Runge-Kutta integrations for bundles of rays (e.g. 4-wide or 8-wide double-precision channels).

### 2.2. Spacetime Metric Implementations

All metric types satisfy the `SpacetimeMetric` concept:
- `FlatMinkowskiMetric`: Pseudo-Euclidean baseline with signature $(-c^2, 1, 1, 1)$.
- `SchwarzschildMetric`: Static spherically symmetric vacuum metric with exact analytical Christoffel symbols.
- `SchwarzschildIsotropicMetric`, `PainleveGullstrandMetric`, `EddingtonFinkelsteinMetric`: Coordinate regularized forms of the Schwarzschild geometry.
- `KerrMetric`: Stationary axisymmetrical geometry in Boyer-Lindquist coordinates, providing conserved Killing quantities & Carter constant invariants.
- `KerrSchildMetric`: Horizon-regular Cartesian formulation $g_{\mu\nu} = \eta_{\mu\nu} + 2H k_\mu k_\nu$.
- `ReissnerNordstromMetric` & `KerrNewmanMetric`: Charged static & rotating electrovacuum spacetimes.
- `SchwarzschildDeSitterMetric`: Cosmological constant $\Lambda$ coupling.
- `FLRWMetric`: Expanding cosmological background with dynamic scale factor $a(t)$ & Hubble parameter $H(t)$.
- `MorrisThorneWormholeMetric`: Spherically symmetric traversable wormhole with throat radius $b_0$.
- `AlcubierreWarpMetric`: Spacetime bubble metric with hyperbolic tangent shaping functions.
- `BssnGrid` & `BssnEvolution`: Numerical relativity module implementing 3+1 conformal BSSN evolution with 4th-order spatial finite differencing, iterative RK4 time advancement, tricubic spatial interpolation, and quintic Hermite temporal interpolation.
- `LemaitreTolmanBondiMetric`: Inhomogeneous spherically symmetric cosmological void metric driven by `LtbProfile` (`include/relativistic/cosmology/lemaitre_tolman_bondi_profile.hpp`), evaluating exact analytical hyperbolic and cycloid shell evolution $R(r, t)$ and $\dot{R}(r, t)$, spatial curvature $k(r) = H_0^2(1 - \Omega(r))r^2$, non-simultaneous bang times $t_B(r)$, and 4th-order spatial derivative stencils $R', \dot{R}', R''$ ([Mathematical Formulation Section 1.10](MATHEMATICAL_FORMULATION.md#110-lemaitre-tolman-bondi-void-metric)).
- `QuintessenceCosmologyMetric` & `ChaplyginCosmologyMetric`: Dynamical dark energy models driven by `QuintessenceBackground` and `ExpansionHistoryBuilder` (`include/relativistic/cosmology/dark_energy_models.hpp`), solving background scalar field evolution over $N = \ln a \in [-6.9078, 1.3863]$ across 4 analytical potentials (`Exponential`, `InversePowerLaw`, `PseudoNambuGoldstone`, `Supergravity`), generalized Chaplygin gas fluids ($P = -A/\rho^\alpha$), and tabulated expansion grids `TabulatedExpansionHistory` ([Section 1.11](MATHEMATICAL_FORMULATION.md#111-quintessence-dark-energy-cosmology) and [Section 1.12](MATHEMATICAL_FORMULATION.md#112-chaplygin-gas-cosmology)).
- `EvaporatingVaidyaMetric`: Semiclassical radiating black hole metric driven by `HawkingRadiation`, `KerrHorizon`, `RenormalizedStressTensor`, `EvaporatingBlackHole`, and `UnruhEffect` (`include/relativistic/semiclassical/hawking_unruh.hpp`), evaluating Kerr horizon surface gravity $\kappa$, Hawking temperatures $T_H$, 2D Polyakov s-wave stress tensors, coupled mass and spin-down integration, and Unruh-DeWitt detector excitation rates ([Section 1.13](MATHEMATICAL_FORMULATION.md#113-evaporating-vaidya-black-hole-metric)).
- `TeVeSSpacetimeMetric`: Tensor-Vector-Scalar covariant modified gravity metric.
- `include/relativistic/metrics/kerr_de_sitter.hpp`: Kerr-de Sitter geometry.
- `compute_kerr_invariants_bl` & `compute_zamo_angular_velocity` (`include/relativistic/metrics/kerr_invariants.hpp`): Conserved energy, axial angular momentum and Carter constant of a Boyer-Lindquist state, and the angular velocity of zero-angular-momentum observers.
- `BardeenKerrShadow` (`include/relativistic/metrics/bardeen_shadow.hpp`): Photon orbit radii and shadow boundary of the Kerr metric for a given observer polar angle.
- `SubsidiarySourceParams` (`include/relativistic/metrics/subsidiary_source_field.hpp`): Compact parameter structure holding position, velocity, mass, Kerr spin parameter $a$, polar horizon radius $r_+$, equatorial horizon radius $r_{h,\text{eq}} = \sqrt{r_+^2 + a^2}$, Kerr ISCO radius, shadow capture radius $r_{\text{cap}} = \max(0.9 M (5.196 - 0.55 a_*^2), 1.05 r_{h,\text{eq}})$, inner and outer accretion disk radii, primary spin axis orientation triad $(\mathbf{f}_x, \mathbf{f}_y, \hat{\mathbf{s}})$, and an internal `KerrSchildMetric<double>` instance.
- `SubsidiarySourceField` (`include/relativistic/metrics/subsidiary_source_field.hpp`): Evaluates ray interactions against subsidiary Kerr black holes in scalar rendering passes: `segment_crosses_horizon` solves the quadratic ray-ellipsoid entry equation in normalized local coordinates; `segment_is_captured` tests ray intersection with the critical shadow capture radius; `segment_crosses_disk` detects equatorial plane crossings ($z_{\text{local}} = 0$) and computes crossing radius, frame-dragged azimuth $\phi_c$, and Keplerian angular momentum ratio $L_z / E$; `compute_weak_field_deflection` computes monopole deflection $2 M b / r^3$, Lense-Thirring spin deflection $-2 a M (\hat{\mathbf{s}} \cdot \hat{\mathbf{n}}) / r^3$, and quadrupole deflection $\frac{15\pi}{8} M^2 / r^3$; `integrate_local_geodesic_correction` integrates 4th-order Runge-Kutta steps in the local Kerr-Schild metric when within strong-field distance $r < \max(r_{\text{disk,out}}, 40 r_h)$; `apply_all_source_corrections` applies distance-sorted deflections sequentially.
- `MultiSourceData` (`include/relativistic/render/software_compute_engine.hpp`): Compiles up to 16 Kerr black holes (`kMaxSources = 16`) storing 4-vectors for position/mass, axis/spin, local frame vectors, horizon dimensions, and accretion disk radii. Drives `trace_multi_source` using Kerr-Schild metric superposition: `ks_field` extracts Boyer-Lindquist radial coordinate $r$ and scalar potential $H = M r^3 / (r^4 + a^2 z^2)$; `ks_source_terms` evaluates spatial gradients $\nabla H$ and $\nabla(\mathbf{k} \cdot \mathbf{p})$; `ms_rhs` and `ms_rk4_step` evaluate superposed Hamiltonian equations of motion; `ms_initial_momentum` constructs observer tetrads via Gram-Schmidt orthonormalization in the superposed metric; `ms_horizon_entry` and `ms_disk_crossing` resolve horizon entries and disk crossings. Implemented identically in GLSL within `shaders/geodesic_tracer_fp64.comp`, utilizing workgroup shared memory (`ms_position_mass`, `ms_axis_spin`, etc.) with workgroup barriers for parallel GPU execution.

### 2.3. Differential Solvers & Integrators

- `GeodesicState<Scalar>` (`include/relativistic/integrators/geodesic_state.hpp`): Cache-aligned 32-byte representation holding 4-position $x^\mu$ and 4-velocity $u^\mu$.
- `RK45AdaptiveIntegrator<MetricType, Scalar>` (`include/relativistic/integrators/rk45_adaptive.hpp`): Dormand-Prince 5(4) embedded adaptive Runge-Kutta scheme with FSAL evaluation, automatic radial time-step limits $0.5 r / |u^r|$ in spherical coordinates, and algebraic constraint projection $g_{\mu\nu} u^\mu u^\nu = \text{const}$ solving the quadratic equation for $u^0$ ([MATHEMATICAL_FORMULATION.md Section 18.1](MATHEMATICAL_FORMULATION.md#181-embedded-adaptive-runge-kutta-tableaus-dormand-prince--cash-karp) and [Section 18.6](MATHEMATICAL_FORMULATION.md#186-algebraic-invariant-constraint-projection--horizon-boundary-classification)). Monitored via `RK45Config` (tolerances, safety factors, horizon modes) and `RK45Stats` (accepted/rejected steps, evaluations, max invariant residual).
- `CashKarpIntegrator<MetricType, Scalar>` (`include/relativistic/integrators/cash_karp.hpp`): Embedded 5(4) 6-stage Runge-Kutta scheme with distinct 4th-order and 5th-order weight vectors, providing wide stability intervals for stiff or oscillatory curved spacetime regions ([MATHEMATICAL_FORMULATION.md Section 18.1](MATHEMATICAL_FORMULATION.md#181-embedded-adaptive-runge-kutta-tableaus-dormand-prince--cash-karp)).
- `Vernier9Integrator<MetricType, Scalar>` (`include/relativistic/integrators/vernier9.hpp`): High-order 16-stage 9(8) embedded Runge-Kutta scheme implementing Jim Vernier's coefficients for ultra-low truncation error across long orbital arcs ([MATHEMATICAL_FORMULATION.md Section 18.2](MATHEMATICAL_FORMULATION.md#182-vernier-98-high-order-16-stage-embedded-runge-kutta-scheme)).
- `GaussLegendreIntegrator<MetricType, Stages, Scalar>` (`include/relativistic/integrators/symplectic_gauss_legendre.hpp`): Implicit Runge-Kutta integrator supporting 2 stages (4th order, `GaussLegendre4`) and 3 stages (6th order, `GaussLegendre6`). Evaluates stage equations via Picard fixed-point iteration to tolerance $10^{-14}$ (`GaussLegendreConfig`), preserving phase space symplectic 2-forms and Killing invariants ([MATHEMATICAL_FORMULATION.md Section 18.3](MATHEMATICAL_FORMULATION.md#183-implicit-symplectic-gauss-legendre-integrators-orders-4-and-6)).
- `Hermite4AarsethIntegrator<MetricType, Scalar>` (`include/relativistic/integrators/hermite4_aarseth.hpp`): 4th-order predictor-corrector scheme evaluating acceleration $\mathbf{a}$ and 4th-order centered finite difference jerk $\mathbf{j} = \dot{\mathbf{a}}$, interpolating snap $\mathbf{s}$ and crackle $\mathbf{c}$ to advance states with Aarseth variable timestep regulation $\Delta t \propto \sqrt{(\|\mathbf{a}\| \|\mathbf{s}\| + \|\mathbf{j}\|^2) / (\|\mathbf{j}\| \|\mathbf{c}\| + \|\mathbf{s}\|^2)}$ ([MATHEMATICAL_FORMULATION.md Section 18.4](MATHEMATICAL_FORMULATION.md#184-hermite-4th-order-predictor-corrector-scheme--aarseth-adaptive-timestep)).
- `AdaptiveStepController<Scalar>` (`include/relativistic/integrators/step_controller.hpp`): Digital filter step regulator supporting `Standard` (elementary integral), `PI30` (proportional-integral, $\beta_I = 0.7/k, \beta_P = 0.3/k$), and `PID42` (proportional-integral-derivative, $\beta_I = 0.6/k, \beta_P = 0.4/k, \beta_D = 0.2/k$) to suppress step-size oscillations ([MATHEMATICAL_FORMULATION.md Section 18.5](MATHEMATICAL_FORMULATION.md#185-digital-filter-adaptive-step-size-controllers-standard-pi30-pid42)).
- `HorizonDetector<Scalar>` (`include/relativistic/integrators/horizon_manager.hpp`): State machine monitoring trajectory radial distance against horizon radius $r_s$ and singularity threshold $\delta_{\text{sing}} r_s$, classifying regional transitions (`Exterior`, `HorizonSurface`, `Interior`, `PhysicalSingularity`) and executing absorption or continuity modes ([MATHEMATICAL_FORMULATION.md Section 18.6](MATHEMATICAL_FORMULATION.md#186-algebraic-invariant-constraint-projection--horizon-boundary-classification)).
- `SphericalPlanarNullIntegrator` (`include/relativistic/core/spherical_planar_null_integrator.hpp`): Planar equatorial null geodesic RK4 integrator operating on `PlanarNullState` $(r, \psi, u^t, u^r, u^\psi)$ with 8th-order Christoffel evaluations.
- `SchwarzschildNullIntegrator` (`include/relativistic/core/schwarzschild_null_integrator.hpp`): Vectorized and scalar RK4 null geodesic integrator operating on `SphericalNullState` and `CartesianNullState`, enforcing angular momentum conservation $\mathbf{h} = \mathbf{r} \times \mathbf{v}$ and unwrap angle transformations.
- `KerrSchildNullIntegrator` (`include/relativistic/core/kerr_schild_null_integrator.hpp`): Cartesian Kerr-Schild null geodesic RK4 integrator operating on `KerrSchildNullState`, computing analytical field gradients and Gram-Schmidt observer tetrad constructions.
- `GeodesicBundle<T, Width>` (`include/relativistic/core/math/geodesic_bundle.hpp`): Structure-of-Arrays (SoA) SIMD ray bundle container executing vectorized null geodesic updates across AVX2, AVX-512, and ARM Neon lanes (`GeodesicBundle4d`, `GeodesicBundle8f`).

#### Runtime Use of the Integrator Selection

- The integrator name stored by `SimulationOrchestrator` is consumed by `SimulationOrchestrator::step_nbody_dynamics`, which selects `SymplecticForestRuthPNIntegrator` when the name contains `Symplectic` or `Gauss` and `RungeKutta4PNIntegrator` otherwise (`include/relativistic/dynamics/pn_integrator.hpp`, [ARCHITECTURE.md](ARCHITECTURE.md#34-orchestrator-state-advance)).
- `SoftwareComputeEngine` does not call the integrators of this section. It uses `step_schwarzschild_null_rk4` (`include/relativistic/core/schwarzschild_null_integrator.hpp`) and, for the exact tracer, a fixed-step RK4 scheme on the Christoffel symbols of the selected metric (`Core::compute_christoffel` with 8th-order differences).
- The ray step is derived from `step_size_factor`, `min_step_size`, `max_step_size`, `far_field_step_scale` and `pole_guard_precision_scale`. `integration_rtol` and `integration_atol` are stored, saved in scenarios and benchmark runs, and displayed, but are not read by the renderer. The step formulas are given in [MATHEMATICAL_FORMULATION.md](MATHEMATICAL_FORMULATION.md#82-step-control-termination-and-space-skipping).
- The compatibility warnings of `include/relativistic/ui/compatibility_notes.hpp` for BSSN with symplectic or Hermite schemes are display-only.

- `CompositeGalaxyGenerator` (`include/relativistic/dark_matter/galaxy_model.hpp`): Synthesizes composite galaxies with exponential stellar disks, Hernquist bulges, and NFW dark matter halos with velocity dispersion sampling and barycenter diagnostics.
- `PostNewtonianSystem`: Container managing multi-body systems, energy conservation tracking, angular momentum bookkeeping, & quadrupole gravitational wave emission ($h_+, h_\times, P_{\text{GW}}$).
- `SphericalHarmonicsGravityModel`: Fully normalized associated Legendre polynomial potential solver up to degree & order 32 (EGM96, LP165, MRO110, Jupiter, Sun models).
- `RungeKutta4PNIntegrator` & `SymplecticForestRuthPNIntegrator` (`include/relativistic/dynamics/pn_integrator.hpp`): Fixed-step integrators of `PostNewtonianSystem`. The orchestrator subdivides each tick into at most 500 sub-steps ([ARCHITECTURE.md](ARCHITECTURE.md#34-orchestrator-state-advance)).
- Spacetime source bodies: A `PostNewtonianBody` with `is_spacetime_source` set carries a Kerr outer horizon derived from its mass and spin (`kerr_outer_horizon_radius`, `kerr_spin_parameter`, `set_spin_state`, `enforce_spacetime_source_invariants`). Absorption and merging are handled by `SimulationOrchestrator::handle_horizon_absorption`; the primary source stays fixed at the origin.
- `InteractionConfig` (`include/relativistic/dynamics/interaction_config.hpp`) & the interaction solver (`interaction_solver.hpp`): Electromagnetic forces (Coulomb and dipole-dipole, with configurable permittivity and permeability), collisions (elastic or inelastic response, rotation, friction, restitution multiplier, contact stiffness scale, position correction), thermodynamics (radiative exchange with an ambient temperature and a coupling scale), fragmentation (integrity loss from collisions and tidal stress, minimum fragment mass, maximum fragments per event) and annihilation (contact scale, opposite-charge requirement). `interaction_compatibility.hpp` produces the warnings displayed in the Interactions tab.
- `BodySurfaceLayerRegistry` (`include/relativistic/dynamics/body_surface_layers.hpp`): Per-body procedural texture layers, at most `Render::kMaxSurfaceLayers` (4) per body. Each layer selects one of 10 patterns, 5 blend modes and 7 region masks (`SurfaceLayerPattern`, `SurfaceLayerBlend`, `SurfaceLayerMask`).
- `BodyManagerWindow` architecture: Reorganized into seven specialized functional tabs:
  1. *Object Catalog*: Manages ordinary N-body objects with flat list and gravitational hierarchy views. Features continuous physical attribute range filtering across mass, radius, temperature, eccentricity, and distance from center with auto-fitting and live breakdown percentages. Multi-selection batch parameter staging supports absolute overrides and relative delta/scaling transformations (mass, radius, position shift, velocity delta, speed factor, temperature delta, uniform inclination).
  2. *Source Catalog*: Manages the central metric source and independent Kerr black holes, their horizon radii, spins, charges, and subsidiary accretion disks. Evaluates mutual horizon overlaps, safe separation constraints, and binary orbital parameters (mass ratio $q$, symmetric mass ratio $\eta$, separation in $r_g$, spin-orbit misalignment $\theta_{LS}$, mutual spin angle $\theta_{S1, S2}$, Peters 1964 coalescence time).
  3. *Create Object*: Single-body drafting with intelligent defaults, starting templates, system scale comparator, and the *Multi-Body Geometric Pattern Generator* synthesizing annular asteroid belts, coplanar debris swarms, and 3D spherical test formations (Plummer polytropic clusters, uniform spheres, Fibonacci lattice shells, infalling/expanding blast waves) across 10 archetype presets with Kirkwood gap simulation and collision-avoidance safeguards.
  4. *Create Source*: Spawns independent Kerr black holes based on observed astrophysical templates (Sagittarius A*, M87*, Cygnus X-1, GW150914 remnant, intermediate-mass black holes, companion Kerr sources) with automatic placement outside horizon overlap zones.
  5. *System Dynamics*: Telemetry for system mass, center-of-mass barycenter, total linear/angular momentum, mechanical energy, quadrupole gravitational wave emission ($P_{\text{GW}}$, dominant $f_{\text{gw}}$, strain $h$ at 10 kpc), center-of-mass velocity shifting, and scoped bulk operations across four target scopes.
  6. *Interactions*: Comprehensive configuration of electromagnetic forces, Hertzian contact mechanics with Baumgarte stabilization, radiative thermodynamics, fragmentation, and matter-antimatter annihilation, coupled with a physical coupling consistency dashboard.
  7. *Randomizer Controls*: Parameter intervals and distribution laws (Uniform, Log-Uniform, Gaussian, Power-Law) governing procedural generation.
- Gravitational Hierarchy Engine (`include/relativistic/ui/body_manager/body_catalog_list.hpp`): Dynamically constructs parent-satellite hierarchy trees using Hill sphere and tidal dominance criteria via `build_gravitational_hierarchy`, reporting Hill radius occupancy percentages, Kozai-Lidov resonance windows ($i_{\text{rel}} \in [39.23^\circ, 140.77^\circ]$), and satellite stability boundaries.
- Local Frenet-Serret RTN Maneuver Injector (`include/relativistic/ui/body_manager/source_property_editor.hpp`): Decomposes orbital motion into local Radial ($\hat{\mathbf{R}}$), Tangential Prograde ($\hat{\mathbf{T}}$), and Normal ($\hat{\mathbf{N}}$) components relative to any designated parent body via `compute_local_frenet_frame`, providing pre-burn trajectory prediction diagnostics (`preview_frenet_maneuver`: eccentricity, semi-major axis, periapsis, apoapsis, plunge warnings) before committing impulses via `apply_frenet_delta_v`. - Batch Object and Source Staging (`include/relativistic/ui/body_manager/body_property_editor.hpp`): Implements `render_batch_object_editor` and `render_batch_source_editor` providing absolute value staging and relative delta/scaling transformations across multi-body selections, including mass scaling, velocity vector offsets, temperature deltas, and uniform inclination alignments.

- Astrophysical System Presets (`include/relativistic/ui/body_manager/system_presets.hpp`): Pre-built systems including the full real Solar System (Sun through Neptune, Pluto, Earth-Moon, Galilean moons: Io, Europa, Ganymede, Callisto, Titan), Inner Solar System, Jovian sub-system, and Earth-Moon frame with automatic physical unit scaling through `ConstantsEngine`.

### 2.5. Relativistic Hydrodynamics (GRHD/GRMHD) & Stellar Physics

- State & Flux Containers (`include/relativistic/hydro/hydro_types.hpp`):
  - `PrimitiveVariables<Scalar>`: 64-byte aligned structure storing rest-mass density $\rho$, isotropic gas pressure $p$, 3-velocity $(v_x, v_y, v_z)$, lab magnetic field $(B_x, B_y, B_z)$, specific internal energy $\varepsilon$, Lorentz factor $W$, specific enthalpy $h$, and comobile magnetic energy density $b^2$. The method `recompute_derived(gamma)` computes $v^2 = \mathbf{v} \cdot \mathbf{v}$, enforces subluminality $v^2 \le 1 - 10^{-15}$, derives $W = (1 - v^2)^{-1/2}$, $b^2 = B^2 / W^2 + (\mathbf{B} \cdot \mathbf{v})^2$, $\varepsilon = p / ((\Gamma - 1)\rho)$, and $h = 1 + \Gamma p / ((\Gamma - 1)\rho)$ ([MATHEMATICAL_FORMULATION.md Section 4.2](MATHEMATICAL_FORMULATION.md#42-conservative-31-form)).
  - `ConservedVariables<Scalar>`: 64-byte aligned structure holding conserved density $D = \rho W$, momentum density $\mathbf{S} = (\rho h W^2 + B^2)\mathbf{v} - (\mathbf{B} \cdot \mathbf{v})\mathbf{B}$, energy density $\tau = \rho h W^2 + B^2 - P_{\text{tot}} - D$, and lab-frame magnetic vector $(B_x, B_y, B_z)$ with overloaded arithmetic operators.
  - `FluxVariables<Scalar>`: 64-byte aligned directional flux container holding $(F_D, F_{S_x}, F_{S_y}, F_{S_z}, F_\tau, F_{B_x}, F_{B_y}, F_{B_z})$.
  - `Metric3Plus1<Scalar>`: Encapsulates lapse $\alpha$, shift $\beta^i$, 3-metric $\gamma_{ij}$ and inverse $\gamma^{ij}$, volume determinant $\sqrt{\gamma}$, and extrinsic curvature $K_{ij}$.
  - `prim_to_con_flat`: Evaluates flat Minkowski mappings from `PrimitiveVariables` to `ConservedVariables`.
  - `compute_flux_1d_x`: Computes the 1D physical flux vector along the $x$-axis from primitive variables.
- Conserved-to-Primitive Inversion (`include/relativistic/hydro/solvers/con2prim.hpp`):
  - `Con2PrimSolver<EOS, Scalar>`: Converts conserved state vectors back to primitive variables subject to floors $p_{\text{floor}} = 10^{-15}$, $\rho_{\text{floor}} = 10^{-15}$, iteration cap 60, and relative tolerance $10^{-12}$ ([MATHEMATICAL_FORMULATION.md Section 4.4](MATHEMATICAL_FORMULATION.md#44-conservative-to-primitive-variable-inversion-formulation)).
  - `solve_hydro`: Solves unmagnetized relativistic hydrodynamic states via 1D Newton-Raphson iteration on pressure $p$. At each iteration with $z = \tau + p + D$, $v^2 = S^2 / z^2$, $W = (1 - v^2)^{-1/2}$, and $h = z / (D W)$, it evaluates objective $f(p) = \Gamma p - (\Gamma - 1)(z / W^2 - D / W) = 0$ with analytical derivative $df/dp = \Gamma - (\Gamma - 1)v^2(1 - 1/h)$, enforcing bracketed bisection fallbacks on $[p_{\min}, p_{\max}]$ whenever $p_{\text{next}}$ escapes or evaluates to non-finite values.
  - `solve_mhd`: Solves relativistic magnetohydrodynamic states via 1D root-finding on scalar $z = \rho h W^2$. At each step, $v^2 = [S^2 z^2 + (\mathbf{S} \cdot \mathbf{B})^2(2z + B^2)] / [z^2 (z + B^2)^2]$, $W = (1 - v^2)^{-1/2}$, $\mathbf{B} \cdot \mathbf{v} = (\mathbf{S} \cdot \mathbf{B})/z$, $b^2 = B^2 / W^2 + (\mathbf{B} \cdot \mathbf{v})^2$, $p = z + B^2 - 0.5 b^2 - \tau - D$, $h = z / (D W)$, and tests residual $f(z) = p - p_{\text{EOS}}(\rho, h) = 0$ with derivative approximation $df/dz = 1 + 0.5(\Gamma - 1)$, reconstructing primitive velocities $\mathbf{v} = \mathbf{S} / (z + B^2) + (\mathbf{S} \cdot \mathbf{B})\mathbf{B} / [z(z + B^2)]$.
- High-Order Spatial Reconstruction (`include/relativistic/hydro/solvers/reconstruction.hpp`):
  - `WENO5Reconstructor<Scalar>`: Computes 5th-order interface states across 5-point stencils $(q_{i-2}, q_{i-1}, q_i, q_{i+1}, q_{i+2})$. Supports Jiang-Shu weights and WENO-Z weights with global smoothness indicator $\tau_5 = |\beta_0 - \beta_2|$ ([MATHEMATICAL_FORMULATION.md Section 4.5](MATHEMATICAL_FORMULATION.md#45-high-order-spatial-reconstruction-schemes)).
  - `MP5Reconstructor<Scalar>`: Evaluates Suresh-Huynh monotonicity-preserving 5th-order reconstruction with curvature parameter $\alpha = 4.0$. Checks original value $q^{\text{orig}}$ against $q^{\text{MP}} = q_0 + \operatorname{minmod}(q_1 - q_0, \alpha(q_0 - q_{-1}))$ and bounds candidates via minmod4 curvature estimates and median selection.
  - `TVDReconstructor<Scalar>`: Evaluates second-order TVD reconstruction using MinMod or Monotonized Central (MC) slope limiters.
  - `reconstruct_primitive_variable_component`: Applies reconstruction across all hydrodynamic primitive fields, clamping density and pressure above $10^{-15}$ and re-scaling velocities to satisfy $v^2 \le 1 - 10^{-14}$.
- Approximate Riemann Solvers (`include/relativistic/hydro/solvers/riemann_solvers.hpp`):
  - `HLLRiemannSolver<EOS, Scalar>`: Evaluates acoustic wave speeds $\lambda_L, \lambda_R$ using local sound speed $c_s = \text{eos.sound\_speed}(\rho, p)$ and relativistic velocity addition $\lambda_\pm = (v_x \pm c_s) / (1 \pm v_x c_s)$, resolving intermediate HLL fluxes ([MATHEMATICAL_FORMULATION.md Section 4.6](MATHEMATICAL_FORMULATION.md#46-multi-wave-approximate-riemann-solvers)).
  - `HLLCRiemannSolver<EOS, Scalar>`: Restores central contact wave speed $\lambda_*$ by solving the quadratic dispersion relation derived from intermediate energy $E^{\text{HLL}}$ and momentum $U^{\text{HLL}}_{S_x}$, evaluating star-region pressure $p_* = -U^{\text{HLL}}_{S_x} \lambda_* + F^{\text{HLL}}_{S_x}$ and star-state conserved vectors $U^*_L, U^*_R$.
  - `HLLDRiemannSolver<EOS, Scalar>`: Resolves five-wave relativistic MHD Riemann problems with intermediate contact and Alfvén waves when transverse magnetic fields are non-zero.
- Solenoidal Magnetic Field Control (`include/relativistic/hydro/solvers/constrained_transport.hpp`):
  - `ConstrainedTransport2D<Scalar>`: Manages staggered 2D grid meshes holding $(n_x + 1) \times n_y$ face-centered $B_x$ components, $n_x \times (n_y + 1)$ face-centered $B_y$ components, and $(n_x + 1) \times (n_y + 1)$ vertex-centered electric field components $E_z$ ([MATHEMATICAL_FORMULATION.md Section 4.7](MATHEMATICAL_FORMULATION.md#47-constrained-transport-ct--solenoidal-magnetic-constraint)).
  - `compute_vertex_electric_fields_from_cell_centered`: Averages cell-centered electric fields $E_z = -(v_x B_y - v_y B_x)$ from four adjacent cell centers to vertices.
  - `update_face_magnetic_fields`: Advances face magnetic fields via discrete curls $\Delta B_x = -(\Delta t / \Delta y) \Delta E_z$ and $\Delta B_y = (\Delta t / \Delta x) \Delta E_z$.
  - `average_to_cell_centers`: Projects face-centered fields to cell-centered primitives ($B_{x,\text{cell}} = 0.5(B_{x,i} + B_{x,i+1})$).
  - `compute_max_divergence`: Measures cell-by-cell numerical divergence $\nabla \cdot \mathbf{B} = (B_{x,i+1} - B_{x,i})/\Delta x + (B_{y,j+1} - B_{y,j})/\Delta y$, guaranteeing machine-precision preservation $\partial_t (\nabla \cdot \mathbf{B}) = 0$.
- 1D Relativistic Hydrodynamic Grid Solver (`include/relativistic/hydro/solvers/grhd_solver.hpp`):
  - `RelativisticHydroSolver1D<EOS, Scalar>`: Manages 1D computational domains of $n_x$ cells with 3 ghost cells on each boundary. Supports `Outflow`, `Periodic`, and `Reflecting` boundary conditions ($v_x \leftarrow -v_x$).
  - `compute_time_step`: Computes CFL-bounded time increments $\Delta t = \text{CFL} \cdot \Delta x / \max_i (|v_{x,i}| + c_{s,i}) / (1 + |v_{x,i}| c_{s,i})$.
  - `step_ssp_rk3`: Advances the system across 3 Runge-Kutta stages using third-order Strong Stability Preserving time integration ($U^{(1)} = U^n + \Delta t L(U^n)$, $U^{(2)} = \frac{3}{4} U^n + \frac{1}{4}(U^{(1)} + \Delta t L(U^{(1)}))$, $U^{n+1} = \frac{1}{3} U^n + \frac{2}{3}(U^{(2)} + \Delta t L(U^{(2)}))$), executing reconstruction, boundary application, and Riemann solver passes at each stage.
  - `initialize_sod_shock_tube`: Sets up the relativistic Sod shock tube problem ($\rho_L = 10.0, p_L = 40.0/3.0, v_L = 0$ on $x < 0.5$; $\rho_R = 1.0, p_R = 10^{-6}, v_R = 0$ on $x \ge 0.5$).
  - `initialize_balsara1_mhd`: Sets up the Balsara-1 relativistic MHD shock tube benchmark ($\rho_L = 1.0, p_L = 1.0, B_{x,L} = 0.5, B_{y,L} = 1.0$; $\rho_R = 0.125, p_R = 0.1, B_{x,R} = 0.5, B_{y,R} = -1.0$).
- Relativistic Hydrostatic Equilibrium & TOV Solver (`include/relativistic/hydro/solvers/tov_solver.hpp`):
  - `TOVConfig<Scalar>`: Holds gravitational constant $G$, speed of light $c$, integration bounds, step bounds ($\Delta r_{\min} = 10^{-4}\,\text{m}$, $\Delta r_{\max} = 20000.0\,\text{m}$), and surface pressure floor fraction ($10^{-14}$).
  - `TOVStarProfile<Scalar>`: Results structure storing central density $\rho_c$, central pressure $p_c$, total gravitational mass $M$, baryonic mass $M_b$, surface radius $R$, surface redshift $z_s = (1 - 2GM/(c^2 R))^{-1/2} - 1$, compactness $C = GM/(c^2 R)$, central redshift $z_c = e^{-\Phi(0)} - 1$, gravitational mass in solar masses, and radially discretized profiles for $r, m(r), m_b(r), p(r), \rho(r), \varepsilon(r), \Phi(r), c_s^2(r)$ ([MATHEMATICAL_FORMULATION.md Section 4.8](MATHEMATICAL_FORMULATION.md#48-tolman-oppenheimer-volkoff-tov-stellar-structure--redshift-formulation)).
  - `solve_star_from_central_density`: Integrates the coupled Tolman-Oppenheimer-Volkoff system $(dm/dr, dm_b/dr, dp/dr, d\Phi/dr)$ using 4th-order Runge-Kutta stepping. Initializes state at $r_0$ via quadratic Taylor series expansions, regulates step size adaptively via local pressure scale height $\Delta r = \operatorname{clamp}(0.05 p / |dp/dr|, \Delta r_{\min}, \Delta r_{\max})$, locates stellar surface radius $R$ via linear sub-step fraction interpolation upon detecting $p \le 0$, and normalizes interior metric potential $\Phi(r)$ to match the analytical exterior Schwarzschild metric $\Phi(R) = \frac{1}{2} \ln(1 - 2GM/(c^2 R))$.
  - `compute_mass_radius_curve`: Sweeps central density across $\log_{10}\rho_c \in [\log_{10}\rho_{\min}, \log_{10}\rho_{\max}]$, evaluates maximum gravitational mass $M_{\max}$, radius at maximum mass, and canonical $1.4 M_\odot$ neutron star radius, tagging dynamic stability boundaries where $\partial M / \partial \rho_c \le 0$.
- Fluid Equations of State (`include/relativistic/hydro/eos.hpp`):
  - `IdealGasEOS<Scalar>`: Gamma-law fluid $p = (\Gamma - 1)\rho \varepsilon$, with sound speed $c_s^2 = \Gamma p / (\rho h)$, enthalpy $h = 1 + \Gamma p / ((\Gamma - 1)\rho)$, and analytical partial derivatives $dp/d\rho = (\Gamma - 1)\varepsilon$ and $dp/d\varepsilon = (\Gamma - 1)\rho$ ([MATHEMATICAL_FORMULATION.md Section 4.3](MATHEMATICAL_FORMULATION.md#43-equations-of-state-eos)).
  - `SyngeEOS<Scalar>` & `MathewsEOS<Scalar>`: Relativistic kinetic models for monoatomic gases with temperature parameter $\theta = p / \rho$, specific enthalpy $h = 2.5\theta + \sqrt{2.25\theta^2 + 1}$, and pressure from enthalpy $p = \rho (h^2 - 1)/(5h)$. Evaluates exact analytical sound speeds: $c_s^2 = \theta / [h (dh/d\theta - 1/h)]$ for Synge, and $c_s^2 = 5\theta (h - 1/h) / [3h \sqrt{2.25\theta^2 + 1}]$ for Mathews.
  - `RelativisticFermiGasEOS<Scalar>`: Degenerate Fermi gas for electrons, neutrons, protons, or custom fermions (`FermiParticleType`). Evaluates characteristic pressure scale $p_0 = m^4 c^5 / (24\pi^2 \hbar^3)$, density scale $\rho_0 = \mu m^4 c^3 / (3\pi^2 \hbar^3)$, dimensionless Fermi momentum $x = (\rho / \rho_0)^{1/3}$, pressure $p(x) = p_0 [x(2x^2 - 3)\sqrt{1 + x^2} + 3\operatorname{asinh}(x)]$, kinetic energy density $E_k(x)$ with 5th-order polynomial series expansions for $x < 0.05$, sound speed $c_s^2 = c^2 x^2 / (3(1 + x^2))$, and Newton-Raphson density inversion from pressure using exact derivative $dp/dx = 8 p_0 x^4 / \sqrt{1 + x^2}$ ([MATHEMATICAL_FORMULATION.md Section 4.9](MATHEMATICAL_FORMULATION.md#49-relativistic-equations-of-state-eos-formulations)).
  - `PolytropicEOS<Scalar>`: Barotropic relation $p = K \rho^\Gamma$, energy density $\varepsilon = \rho + p / (\Gamma - 1)$, specific enthalpy $h = 1 + \frac{\Gamma K}{\Gamma - 1}\rho^{\Gamma - 1}$, and density inversion $\rho(p) = (p / K)^{1/\Gamma}$.
  - `PiecewisePolytropicEOS<NumPieces, Scalar>`: Multi-segment polytrope with continuity matching across dividing densities $\rho_{\text{div}, i}$, piecewise indices $\Gamma_i$, and energy shift constants $a_i = a_{i-1} + \frac{P_{i-1}}{\rho_{\text{div}, i-1} c^2} (\frac{1}{\Gamma_{i-1} - 1} - \frac{1}{\Gamma_i - 1})$ guaranteeing continuous specific enthalpy $h(\rho) = 1 + a_i + \frac{\Gamma_i}{\Gamma_i - 1}\frac{p}{\rho c^2}$ and energy density $\varepsilon(\rho) = (1 + a_i)\rho c^2 + \frac{p}{\Gamma_i - 1}$.
  - `TabulatedNuclearEOS<Scalar>`: 3D tabulated nuclear equation of state with trilinear interpolation over $(\log_{10}\rho, \log_{10}T, Y_e)$. Implements built-in calibrated presets for SFHo, Shen, LS220, SLy4, and APR4 models, binary search density inversion along the cold slice, and serializes tables to custom binary containers via `to_hdf5_container` and `from_hdf5_container` ([FILE_FORMATS.md Section 3.2](FILE_FORMATS.md#32-standard-group-hierarchy)).
- Relativistic Accretion Disks and Magnetospheres:
  - `NovikovThorneDisk` (`include/relativistic/hydro/novikov_thorne.hpp`): Evaluates Page-Thorne analytical flux distribution $F(r) = \frac{3GM\dot{M}}{8\pi r^3} \frac{f(x)}{x(x^3 + a_*)}$, cubic roots $x_1, x_2, x_3$, ISCO, marginally bound and photon orbit radii, scale height $h(r) = c_s / \Omega_K$, surface density $\Sigma(r) = \dot{M}/(3\pi \nu)$, radiative efficiency $\eta = 1 - E_{\text{ISCO}}$, and local blackbody spectrum sampling.
  - `FishboneMoncriefTorus` (`include/relativistic/hydro/fishbone_moncrief.hpp`): Stationary magnetized thick accretion torus in Kerr spacetime with constant specific angular momentum $l = -u_\phi / u_t$, effective potential $W(r, \theta) = \frac{1}{2} \ln(u_t^2)$, polytropic equilibrium density $\rho(r, \theta) = [(\Gamma - 1)(h - 1) / (\Gamma K)]^{\frac{1}{\Gamma - 1}}$, and local Boyer-Lindquist four-velocities.
  - `BlandfordZnajekModel` (`include/relativistic/magnetosphere/blandford_znajek.hpp`): Horizon-threading force-free jet magnetosphere evaluating stream functions $A_\phi(r, \theta)$, Znajek boundary conditions, toroidal magnetic field generation, Poynting power extraction, and polarized synchrotron transfer along null rays.

### 2.8. Orchestration, Scheduling & User Interface

### 2.9. Rendering Back Ends

- Entry points: `SoftwareComputeEngine::dispatch_fp64`, `dispatch_fp32` and `dispatch_double_single`. The scalar tracer is used when the metric requires the exact path (`requires_exact_metric_path`) or when `USE_SCALAR_PIPELINE` is set. Otherwise the SIMD tracer is used; when bodies are present, `compute_body_screen_tiles` marks the 32 x 32 pixel tiles covered by body bounding volumes, the SIMD tracer skips the marked tiles and the scalar tracer renders them with a per-tile list of candidate bodies.
- SIMD tracers: `GeodesicBundle4d` (4 double-precision lanes) and `GeodesicBundle8f` (8 single-precision lanes). They trace the Schwarzschild null equations only, without 3D bodies, exact metrics or subsidiary sources. Only the double-precision SIMD tracer applies the Carter pre-classification and the far-field step factor.
- Specialized exact tracers in `SoftwareComputeEngine`:
  - `trace_kerr_schild_photon`: Integrates Boyer-Lindquist Kerr spacetimes in Cartesian Kerr-Schild coordinates using `step_kerr_schild_null_rk4`, resolving geodesics across the horizon without coordinate singular points.
  - `trace_planar_photon`: Solves equatorial and orbital-plane null geodesics for static spherical metrics (`SchwarzschildDeSitterMetric`, `ReissnerNordstromMetric`) using `step_planar_null_rk4`.
  - `trace_spherical_photon`: Numerically integrates geodesics for general spherically symmetric spacetimes (`LemaitreTolmanBondiMetric`, `VaidyaEvaporatingMetric`, `EddingtonFinkelsteinMetric`, `PainleveGullstrandMetric`, `TeVeSSpacetimeMetric`) via analytical metric tetrad projection.
  - `trace_multi_source`: Evaluates photon trajectories through up to 16 interacting Kerr black holes using Cartesian Kerr-Schild superposition. Automatically invoked when `preset_3d == 8` bodies exist in the catalog alongside the central mass. Computes initial null 4-momentum via Gram-Schmidt tetrad lifting (`ms_initial_momentum`), steps trajectories with adaptive multi-center RK4 integration (`ms_rk4_step`), resolves simultaneous horizon entries (`ms_horizon_entry`), and accumulates radiance from primary and subsidiary accretion disks sorted by ray parameter (`ms_disk_crossing`).
- Precision: `dispatch_double_single` forwards to `dispatch_fp32`; the render mode named double-single therefore integrates rays in `float`, and exact-metric rays are still traced in `double`. `DoubleSingle` (`include/relativistic/render/double_single.hpp`) provides error-free sum and product transformations, arithmetic operators, `ds_sqrt`, `ds_sin`, `ds_cos` and `ds_atan2`, but is not referenced by `SoftwareComputeEngine`. The shader `shaders/geodesic_tracer_ds.comp` is part of the repository, whereas `VulkanComputeExecutor` loads only `geodesic_tracer_fp64.comp.spv`.
- Disk parameters: the scalar double-precision tracer and both single-precision tracers use the constants 18000 K and $g^4$ in the disk model, and the SIMD and exact double-precision tracers use `disk_temperature_scale_k`, `disk_temperature_floor_k` and `disk_doppler_beaming_exponent` (see [MATHEMATICAL_FORMULATION.md](MATHEMATICAL_FORMULATION.md#82-step-control-termination-and-space-skipping)).
- Spacetime source bodies (`preset_3d == 8`): `collect_subsidiary_sources` extracts them from the body list. In single-source spacetimes, the scalar tracer evaluates subsidiary deflection (`apply_subsidiary_deflection_step`), horizon absorption (`segment_crosses_horizon`), shadow capture (`segment_is_captured`), disk crossing (`segment_crosses_disk`), and horizon rim emission. In multi-source configurations, execution routes directly to `trace_multi_source`.
- Per-pixel output: `GpuPixelOutput` stores color, alpha, redshift, affine parameter, `PixelFlags` (horizon absorbed, celestial hit, accretion disk hit, photon sphere proximity, body surface hit) and the iteration count. `RenderFlags` assigns bits 0 to 3 to the skybox mode and bits 4 to 18 to the options (grid skybox, scalar pipeline, per-frame threads, tiled distribution, texture reallocation, level of detail, space-skipping, adaptive tile prepass, 3D bodies, body Doppler beaming, body gravitational redshift, atmosphere scattering, body shadows, bodies-only mode, body disk occlusion).
- Camera constants: `GpuCameraPushConstants` defines `operator==`; the viewport compares the new constants with the previous ones to decide whether a new dispatch is required. `GpuBodyData` is converted to the 704-byte `GpuBodyGpuLayout` for the Vulkan storage buffer.
- Sky: the procedural sky combines a starfield with a galactic band, an optional coordinate grid, deep-field galaxies, dust clouds and star clusters, followed by hue, saturation and background offset; `sky_background_source` selects an equirectangular panorama (`SkyPanoramaLoader`) instead. Panoramas are described by `sky_panorama_catalog.hpp`.
- Body rendering: `evaluate_3d_bodies` intersects rays with oblate, prolate, or triaxial ellipsoids, evaluating 27 surface texture modes: 13 procedural shaders and 14 imported photographic texture maps (Earth Blue Marble, Sun Photosphere, Mercury Cratered, Venus Atmosphere, Venus Radar Altimetry, Mars Basalt, Jupiter Zonal Bands, Saturn Belts, Uranus Methane, Neptune Vortex, Ceres, Eris, Haumea, Makemake) with selectable 1K/2K resolution and Day/Night/Automatic twilight terminator blending. Evaluates up to four procedural `BodySurfaceShading` layers with 10 patterns, 5 blend modes, and 7 region masks.
- 3D Body Illumination System (`BodyLighting`, `include/relativistic/render/bodies/body_lighting.hpp`): Evaluates direct irradiance, specular reflection, and inter-body radiant energy transport across ray-traced celestial body surfaces in CPU rasterization and Vulkan GPU compute shaders:
  - *Light Source Modes (`LightSourceMode`)*: CentralSource (0, fixed at origin $(0, 0, 0)$), CameraHeadlight (1, positioned at camera coordinates), FixedDirection (2, distant directional key light oriented via horizontal azimuth $\phi_L \in [-180^\circ, 180^\circ]$ and elevation $\theta_L \in [-90^\circ, 90^\circ]$), FixedPoint (3, localized point light source at Cartesian coordinates $\mathbf{x}_{\text{light}}$), NearestEmissiveBody (4, dynamic nearest-neighbor query across catalog bodies with $I_{\text{em}} > 10^{-3}$, modulated by emitter primary color), SpecificBody (5, assigned catalog emitter $B_{\text{id}}$ with primary color modulation), and Unlit (6, uniform unit diffuse shading bypassing directional light and shadows).
  - *Photometric Attenuation (`LightAttenuationMode`)*: None (0, unattenuated constant irradiance) and InverseSquare (1, $\mathcal{E}(d) = I_{\text{light}} \min((d_{\text{ref}}/d)^2, 64.0)$), clamping maximum amplification to $64\times$ to avoid floating-point overflow near emitter centroids.
  - *Terminator Transition Softness*: Evaluates wrapped diffuse shading $D(s) = \operatorname{clamp}((\mu + s)/(1 + s), 0, 1)$ with parameter $s \in [0.0, 1.0]$. For photographic Earth textures with Day/Night/Automatic blending, the twilight transition width uses $s_{\text{eff}} = \max(s, s_{\text{earth}})$, evaluating quintic polynomial blending $w_{\text{day}} = t^3 (t(6t - 15) + 10)$ in the GPU shader and cubic smoothstep $w_{\text{day}} = t^2 (3 - 2t)$ on CPU.
  - *Blinn-Phong Specular Reflection*: Evaluates half-vector $\hat{\mathbf{H}} = (\hat{\mathbf{L}} - \hat{\mathbf{d}}) / \|\hat{\mathbf{L}} - \hat{\mathbf{d}}\|$ with shininess exponent $n_{\text{spec}} = 4 + 80(1 - \varrho)$, specular scale multiplier $s_{\text{spec}}$, and microfacet roughness $\varrho \in [0.0, 1.0]$.
  - *Shadow Occlusion Testing*: Casts linear shadow rays $\mathbf{r}(t) = \mathbf{h} + t \hat{\mathbf{L}}$ from surface intersection $\mathbf{h}$ toward localized light sources ($t \in [10^{-5}, d]$). Evaluates ray intersections against bounding ellipsoids of other catalog bodies and the central horizon sphere of radius $r_h$.
  - *Multi-Source Inter-Body Emission Lighting (`emitted_irradiance`)*: Accumulates irradiance from active emitting celestial bodies ($I_{\text{em}, j} > 10^{-3}$) onto facing surfaces, weighted by distance attenuation $\min((d_{\text{ref}, e}/d)^2, 16.0)$, Lambertian cosine factor $\max(0, \hat{\mathbf{N}} \cdot \hat{\mathbf{L}}_j)$, emitter primary color $\mathbf{C}_{\text{primary}, j}$, and global gain multiplier $G_{\text{em}}$.
  - *Detail Level Presets (`BodyLightingDetail`)*: Minimal (0, ambient and wrapped diffuse only; shadow rays and emission lighting bypassed), Reduced (1, shadow occlusion testing capped to `body_shadow_caster_limit` $\le 512$ and emission sources capped to `body_emission_source_limit` $\le 512$), and Full (2, unrestricted shadow occlusion testing and emission accumulation across all catalog bodies).
  - *Quick Presets*: Stellar Default (0), Headlight (1), Studio Key (2), Unlit (3), Dramatic (4), Reset (5).
  - *Shader Implementation*: Evaluated in GLSL within `shaders/geodesic_tracer_fp64.comp` via `resolve_body_light`, `light_is_occluded`, and `emitted_irradiance`, and in C++ within `SoftwareComputeEngine::evaluate_3d_bodies`.
- Procedural Multi-Layer Skybox Engine (`SkyboxRenderer`, `include/relativistic/render/skybox_renderer.hpp`): Evaluates celestial environment radiance along escaping null geodesics. Parameterized by `ProceduralSkySettings` and packed into the 1808-byte `GpuSkyProfile` uniform structure transferred to GPU compute shaders at binding 0 (`CameraParams.sky`). Features:
  - *Spherical Voxel Partitioning (`SphericalPartition`)*: Divides $\mathbb{S}^2$ into equal-area cells with grid resolution $N_{\text{grid}} = \operatorname{clamp}(14\sqrt{\rho_{\text{stars}} Q_{\text{eff}}}, 6, 120)$.   - *Star Point Spread Function Models (`StarProfileModel`)*: Gaussian (0), Lorentzian (1), Moffat (2), AiryDiffraction (3, using rational Chebyshev polynomial approximation for Bessel $J_1(x)$), HardDisc (4), DiffractionSpikes (5, with 4, 6, or 8 spikes, rotation angle, radial length, and exponential decay), PinpointDirac (6, with concentration parameter $\eta_{\text{dirac}}$), and CinematicBloom (7, with core Gaussian and secondary exponential halo).
  - *Star Placement Density Models (`StarPlacementModel`)*: UniformEqualArea (0), GalacticDisk (1, exponential vertical scale-height falloff from galactic plane), FractalClustered (2, 3D FBM noise clustering), DualPopulation (3, 70% thin-disk and 30% spherical isotropic halo), SpiralArmDensity (4, logarithmic two-arm spiral density modulation), and ConstellationAssociations (5, spatial hash noise clustering).

  - *Blackbody Chromaticity*: Evaluates normalized surface temperature $T^* \in [0.0, 1.0]$ with temperature bias $\tau_{\text{bias}}$, mapping into Wien chromatic intervals ($T^* < 0.20$ red M-dwarf, $0.20 \le T^* < 0.45$ orange K-dwarf, $0.45 \le T^* < 0.70$ yellow G-type, $0.70 \le T^* < 0.88$ white A-type, $T^* \ge 0.88$ blue O/B supergiant) scaled by color variation parameter $k_{\text{var}}$.
  - *Volumetric Galactic Nebulae*: Evaluates exponential disc scale-height envelopes with plane normal $\hat{\mathbf{n}}_{\text{gal}}$, core asymmetry concentration toward $\hat{\mathbf{a}}_{\text{core}}$, divergence-free 3D curl-noise advection ($\nabla \times \mathbf{\Psi}$), multi-layer FBM noise accumulation ($1$ to $5$ layers) across primary, secondary, and tertiary emission colors, gas contrast power-law exponents, ionization glow, and fractal ridged dust extinction lanes obeying Beer-Lambert exponential absorption.
  - *Open and Globular Star Clusters*: Distributed across galactic halo and plane structures, evaluating Plummer potential surface brightness profiles $I(\theta) \propto [1 + \theta^2 / (0.40 R_{\text{cluster}}^2 s_{\text{spread}})]^{-c_{\text{conc}}}$ and generating explicit member stars ($4$ to $256$) via Plummer cumulative mass inversion $r_m = R_{\text{core}} \sqrt{u^{2/3} / (1 - u^{2/3})}$.
  - *Deep-Field Background Galaxies*: Distributed across spherical rings, evaluating composite bulge-disk profiles across 6 morphologies (`GalaxyMorphologyModel`: GrandDesignSpiral, FlocculentSpiral, BarredSpiral with Gaussian bars, GiantElliptical with de Vaucouleurs Sersic profiles, Lenticular with resonant dust rings, RingGalaxy) with inclined near-side dust extinction.
  - *Quasars*: Compact unresolved nucleus coupled with a collimated relativistic synchrotron jet profile $\mathcal{P}_{\text{jet}}$ and relativistic Doppler boosting amplification $\delta^3 = [\Gamma(1 - \beta \cos\theta_{\text{view}})]^{-3}$.
  - *Pulsars & Supernova Remnants*: Pulsar rotating magnetic dipole lighthouse sweep beam inclined by magnetic tilt $\alpha_{\text{tilt}}$ relative to spin axis, toroidal pulsar wind nebula (PWN) glow, and SNR expanding triaxial ellipsoid shells with fractal filamentary turbulence and reverse-shock interior glow.
  - *Celestial Coordinate Grid*: Spherical coordinates $(\delta, \alpha)$ evaluating line coverage with pixel footprint $\epsilon_{\text{px}}$, antialiased feathering, polar convergence singularity tapering $\kappa_{\text{pole}}$, major circles, minor circles, degree tick marks, and 5 cell fill modes (`GridCellFillMode`: None, Checkerboard2Color, CyclicPalette, CheckerboardPattern, RandomHashFill) indexing an editable 16-color palette.
  - *Shader Implementation*: Implemented in GLSL within `shaders/geodesic_tracer_fp64.comp` and `shaders/cluster_tile_tracer_fp64.comp`, and in C++ within `include/relativistic/render/skybox_renderer.hpp`.

### 2.13. Distributed Computing & Cluster Engine

The distributed subsystem (`include/relativistic/distributed/`) provides network-distributed compute offloading across homogeneous or heterogeneous machines:

- `ClusterOrchestrator` (`cluster_orchestrator.hpp`): Master coordinator managing peer sessions (`MasterPeerSession`), network pumps, cryptographic handshakes, body catalog broadcasting via `BodyCatalogStore`, frame tile dispatch (`dispatch_frame`), work stealing, and compute job management (`run_compute_job`). Routes five task classes: interactive viewport tiles, capture studio bands, N-body row blocks (`evaluate_nbody_accelerations`), Monte Carlo geodesic ensembles (`run_geodesic_ensemble`), and gPCE stochastic quadratures (`evaluate_stochastic_pce_quadrature`).
- `DistributionScheduler` (`distribution_scheduler.hpp`): Evaluates normalized capacity allocations $\Omega_i(t)$ via `compute_capacity_shares`, tile quotas $K_i$ via `compute_tile_quotas`, Bresenham credit interleaving, dynamic deadlines via `estimate_tile_compute_seconds`, three-tier work stealing (`collect_expired`, `steal_speculative`, `reclaim_node`), and atomic frame completion detection (`is_frame_complete`).
- `NetworkTransport` (`network_transport.hpp`): Transport abstraction wrapping ENet/UDP. Channel 0 handles reliable sequenced control traffic (handshakes, clock sync, catalog chunks, cancellations); Channel 1 handles unsequenced unreliable-fragmented tile payloads up to $256\,\text{KiB}$, preventing head-of-line blocking stalls.
- `CryptoChannel` (`crypto_channel.hpp`): AEAD encryption layer implementing X25519 ECDH key agreement (`generate_node_identity_keys`, `perform_handshake_server`, `perform_handshake_client`), HKDF-SHA256 key derivation with `"RelativisticEngineV1"`, ChaCha20 symmetric stream cipher (`chacha20_block`), and Poly1305 MAC tag generation (`poly1305_generate_tag`) over the 28-byte authenticated header and ciphertext with a 64-packet sliding replay window (`check_and_update_replay_window`).
- `PacketEnvelope` (`packet_protocol.hpp`): 48-byte binary envelope aligned to 16 bytes:
  - Magic identifier: `0x52454C44` (`RELD`).
  - Header fields (28 bytes authenticated AAD): `protocol_version` (uint16_t, 1), `PacketType` (uint16_t opcode), `session_identifier` (uint32_t), `packet_sequence` (uint32_t), `frame_index` (uint32_t), `payload_bytes` (uint32_t), `payload_crc32` (uint32_t).
  - Trailing fields: `authentication_tag` (16 bytes Poly1305 MAC) and 4-byte padding (`alignas(16)`).
  - Validation: `validate_envelope_structure(envelope, buffer_size)` verifies packet magic, version, and buffer bounds.
- `TaskPayloads` (`task_payloads.hpp`): Binary payload definitions:
  - `RenderTileTaskPayload`: Encapsulates `RenderTileTaskHeader` (16 bytes packed: tile index, tile grid coordinates, step budget, flags, compression type), dispatch timestamp (double, 8 bytes), and `GpuCameraPushConstants` (1808 bytes). Serialized via `serialize_render_tile_task` ($k\text{RenderTileTaskPayloadBytes} = 1832$) and `deserialize_render_tile_task`.
  - `RenderTileResultPayload`: Encapsulates `RenderTileResultHeader` (24 bytes packed: tile index, frame index, pixel count, compression type, uncompressed bytes, execution microseconds) and `compressed_bytes` (uint32_t, 4 bytes).
  - Grid geometry: `tile_grid_columns(width)`, `tile_grid_rows(height)`, and `resolve_tile_geometry(tile_index, width, height)` mapping $32 \times 32$ work units.
- `TileCodec` & `TileSanitizer` (`compression_codecs.hpp`): Multi-tier tile compression codecs:
  - `DirectRaw`: Uncompressed raw 32-byte pixel stream for low-latency LAN links.
  - `QoiHdrRle`: Converts RGB and alpha to 16-bit half-floats via `HalfFloat::to_bits`, maintains a 64-entry hash table, encodes short runs (1–64) and long runs (65–16448), and emits partial delta updates with a 6-bit field difference bitmask.
  - `Lz4Block`: Block compression via `LZ4_compress_fast` with automatic fallback to `DirectRaw` when compressed bytes equal or exceed uncompressed bytes or when acceleration $\ge 8$.
  - `TileSanitizer`: Evaluates AVX2/Neon vector sweeps validating IEEE 754 floating-point finiteness, repairing non-finite alpha and redshifts, and clamping radiant flux to $[0.0, 1.0 \times 10^8]\,\text{W/m}^2/\text{sr}$. Reports modifications through `SanitizationReport`.
- `DiscoveryService` (`discovery_service.hpp`): Peer discovery executing periodic UDP multicast beacons on `239.255.77.88:42424` using the 72-byte `DiscoveryBeacon` structure with CRC32 checksum verification, domain-separated cluster namespace tag derivation (`derive_discovery_cluster_tag`), and thread-safe event queue draining (`drain_events`).
- `NodeRegistry` (`node_registry.hpp`): Thread-safe registry tracking active nodes, peer bindings, hardware capabilities, RFC 6298 RTT estimators (`LatencyEstimator`), throughput rates (`ThroughputEstimator`), and watchdog timeout enforcement.
- `BodyCatalogStore` & `NBodyStateStore` (`body_catalog.hpp`, `compute_kernels.hpp`): Chunked binary streaming stores assembling body collections (`BodyCatalogChunkHeader`, 24 bytes) and N-body states (`NBodyStateChunkHeader`, 32 bytes) across datagrams, retaining up to 4 completed frames/jobs.
- `TileRenderer` & `ClusterWorkerService` (`tile_renderer.hpp`, `worker_service.hpp`, `worker_options.hpp`): Autonomous execution engine on worker nodes driving `VulkanComputeExecutor` with dedicated SPIR-V shader `cluster_tile_tracer_fp64.comp` or CPU multi-threading. Returns `TileRenderOutcome` (`completed`, `cancelled`, `execution_time_us`). Supports cooperative cancellation via atomic flags (`cancel_flag`).
- `GpuNBodyExecutor` (`gpu_nbody_executor.hpp`): GPU-accelerated post-Newtonian acceleration evaluator executing `nbody_accel_fp64.comp` in 64-bit precision on Vulkan with uniform parameter binding 0, input state binding 1, output result binding 2, workgroups of 64 threads, and host-coherent staging buffer readback.

### 2.14. Application Lifecycle, Platform Bootstrap & Startup Window Subsystem

The application lifecycle and startup instrumentation subsystem (`include/relativistic/startup/`) provides host integration, inter-process synchronization, and progress tracking prior to workspace presentation:
- Platform Bootstrap (`platform_bootstrap.hpp`):
  - `enable_per_monitor_dpi`: Dynamically queries `SetProcessDpiAwarenessContext` in `user32.dll` to establish per-monitor v2 DPI awareness (`DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2`, handle value `-4`).
  - `register_application_identity`: Calls `SetCurrentProcessExplicitAppUserModelID` in `shell32.dll` registering `Wartets.RelativisticEngine` for Windows taskbar grouping and notification routing.
  - `HeapSetInformation`: Enables immediate termination on heap corruption (`HeapEnableTerminationOnCorruption`).
  - `normalize_working_directory`: Inspects the working directory for required asset subdirectories (`shaders`, `scenarios`). If absent, inspects the directory containing the running executable (`executable_directory`) and up to 4 parent ancestor directories, rebinding the current path via `std::filesystem::current_path` to guarantee deterministic asset resolution across diverse launch environments.
  - Diagnostic Alert Boxes: `show_notice` and `show_fatal_error` format diagnostic text to `stderr` and display native modal dialogs (`MessageBoxW`) on Windows platforms.
- Single-Instance Guard (`single_instance_guard.hpp`):
  - Inter-Process Synchronization: Windows implementations create a named Win32 mutex `Local\Wartets.RelativisticEngine.SingleInstance`. If `GetLastError()` returns `ERROR_ALREADY_EXISTS`, the acquisition fails. POSIX platforms open a user-isolated lockfile `/tmp/wartets-relativistic-engine-<uid>.lock` using `O_RDWR | O_CREAT | O_CLOEXEC` and evaluate non-blocking advisory file locking via `::flock(descriptor, LOCK_EX | LOCK_NB)`.
  - Existing Window Activation: When an existing instance is detected, `activate_existing_instance` queries top-level windows via `FindWindowW` searching for the application title, restores iconic windows with `ShowWindow(target, SW_RESTORE)`, and transfers focus via `SetForegroundWindow(target)`.
- Multi-Stage Startup Progress Tracking (`startup_progress.hpp`):
  - `StartupRange`: Defines contiguous sub-ranges $[R_{\text{begin}}, R_{\text{end}}]$ with clamped local interpolation $f_{\text{global}} = R_{\text{begin}} + (R_{\text{end}} - R_{\text{begin}}) \cdot \operatorname{clamp}(f_{\text{local}}, 0, 1)$.
  - `StartupStage`: Defines standardized progress partitions:
    - `Runtime`: $[0.00, 0.05]$ (Platform bootstrap, logging, command line).
    - `Settings`: $[0.05, 0.12]$ (Persistent configuration migration and ingestion).
    - `Simulation`: $[0.12, 0.22]$ (Orchestrator and physics subsystem instantiation).
    - `WindowSystem`: $[0.22, 0.28]$ (GLFW window initialization and display queries).
    - `GraphicsContext`: $[0.28, 0.36]$ (OpenGL context creation and extension binding).
    - `RenderBackend`: $[0.36, 0.70]$ (Vulkan compute context and shader compilation).
    - `Interface`: $[0.70, 0.84]$ (ImGui contexts, dock trees, font generation).
    - `Content`: $[0.84, 0.96]$ (Scenario resolution, body catalog loading, textures).
    - `Finalize`: $[0.96, 1.00]$ (Workspace ready, splash window handoff).
  - Progress Mutators: `report` updates stage and detail strings, advancing the global fraction monotonically; `note` applies asymptotic creep increments toward the current range ceiling ($f \leftarrow f + 0.16(R_{\text{end}} - f)$); `complete` sets the fraction to $1.0$ and phase to `Completed`; `fail` records fatal startup errors.
  - Cooperative Cancellation: `request_cancel` sets an atomic boolean flag; `throw_if_cancelled` throws `StartupCancelled` to abort long-running initialization loops cleanly.
  - Active Progress Singleton: Thread-safe slot accessors `set_active_progress` and `active_progress` support progress notifications from worker threads without explicit object coupling.
- Native Win32 Startup Window (`startup_window.hpp`):
  - Thread Architecture: Executes on an autonomous worker thread (`std::thread`), creating an unconstrained `WS_POPUP` window with class `RelativisticEngineStartupWindow` and drop shadow style `CS_DROPSHADOW`. Communicates thread readiness through `std::promise<bool>` and terminates on `WM_APP + 2U` (`kMessageClose`).
  - GDI Double-Buffering: Employs two `Surface` memory device contexts (`backdrop_` for static visual branding and `frame_` for dynamic status overlays) blitted to screen on `WM_PAINT` via `BitBlt(SRCCOPY)` to eliminate flicker.
  - Per-Monitor Dynamic Typography & Layout: Re-queries monitor DPI upon `WM_DPICHANGED`, scaling font metrics and layout rectangles dynamically. Synthesizes eight specialized fonts (`fonts_.title`, `header`, `section`, `stage`, `body`, `body_bold`, `small`, `mono`).
  - Animated Progress Easing: A 15 ms timer (`kEaseTimerId`) smooths displayed progress fractions toward target fractions using exponential relaxation ($f_{\text{disp}} \leftarrow f_{\text{disp}} + 0.2(f_{\text{target}} - f_{\text{disp}}) \pm 0.0004$), invalidating only the progress rect bounds.
  - Elapsed Clock Timer: A 100 ms timer (`kClockTimerId`) invalidates the time readout, rendering formatted seconds or minute-second representations ($M\text{m } S.S\text{s}$) from launch to completion.
  - Interactive Action Controls: Handles hit testing (`WM_NCHITTEST`), mouse movements, and button clicks across five control bounds: Minimize, Close/Cancel (which triggers cooperative startup cancellation), License button, Documentation button, and GitHub repository button (invoking external URLs via `ShellExecuteW`).
  - Modern Window Chrome: Sets DWM attribute 33 (`DWMWA_WINDOW_CORNER_PREFERENCE`) to value 1 (`DWMWCP_ROUND`) to enforce system rounded window corners on Windows 11.
